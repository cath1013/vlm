# 몇 초 앞까지 예측할 수 있는가

**질문** — `traffic_llm` 은 미래 5초를 1초짜리 구간(bucket) 5개로 쪼개서 묻는다.
그 5개가 전부 답할 수 있는 질문인가?

**답** — 아니다. **k=1(0~1초)만 풀리고, k=3(2~3초)부터는 찍는 것과 다를 바 없다.**
2초 너머의 충돌은 지금의 움직임이 아니라 *아직 하지 않은 동작*이 결정하기 때문이다.

---

## 먼저 — 이 실험은 모델을 안 쓴다

여기서 쓰는 것은 **기하 (geometry)** 뿐이다. 좌표와 거리 계산, 그게 전부다.
학습도 없고 신경망도 없고 LLM 도 안 부른다.

차 두 대가 이렇게 있다고 하자.

```
A 차   위치 (0, 0)     동쪽으로 초속 10m
B 차   위치 (40, 0)    서쪽으로 초속 10m
```

**1초 뒤 어디 있나** — 곱하기다.

```
A: (0 + 10×1, 0)  = (10, 0)
B: (40 − 10×1, 0) = (30, 0)
```

**얼마나 가까운가** — 빼기다. 단, 중심끼리가 아니라 **차체끼리** 잰다.

```
중심 사이 거리 = 30 − 10 = 20m
차 길이가 4.6m 씩이므로 몸통 사이 간격 = 20 − 4.6 = 15.4m
```

이것을 0.1초마다 반복하면 그 구간에서 **가장 가까워지는 간격**이 나온다.
차가 돌아 있으면 회전한 사각형끼리 재므로 계산이 조금 길어질 뿐, 원리는 같다.

> **중심 거리를 쓰면 안 된다.** 정답 데이터의 접촉 기준("두 차 길이의 절반 합 + 여유
> 2m")을 모든 쌍에 적용하면 승용차 둘이 6.6m 다 — 차선에 줄 서 있는 차가 전부
> "접촉"으로 잡힌다. 실제로 구간의 64% 에서 발동했다.

---

## 이 값 하나로 판정한다

구간마다 "가장 가까워지는 간격" 한 개가 나온다. 그 값이 정답을 얼마나 잘 가르는지를
**AUC** 로 본다.

```
AUC 1.0   완벽히 가른다
AUC 0.5   전혀 못 가른다 = 정보 없음
```

모델도 학습도 없는 순수 계산이므로, **여기서 안 갈리면 그 구간은 물리적으로
결정되지 않는다**는 뜻이다. 어떤 방법을 써도 마찬가지다.

k=4·k=5 는 **0.5 미만** — 찍는 것보다도 못하다.

## `never` 가 87.6% 를 맞힌다 — 정확도만 보면 속는다

**정책 (policy)** 은 답을 정하는 규칙이다. 넷을 비교했고, 앞의 셋은 일부러 멍청하게
만든 것이다.

| 정책 | 하는 일 |
|---|---|
| **never** | 무조건 "사고 안 남". 데이터를 아예 안 본다 |
| **always** | 무조건 "사고 남". 역시 안 본다 |
| **random** | 동전 던지기 |
| **gap** | 위에서 구한 최소 간격이 임계값보다 작으면 "사고 남" |

2,394개 구간 중 실제 사고는 260개(10.9%)뿐이다. 그래서:

| 정책 | 정확도 | **균형정확도** | 오탐 (FP) |
|---|---:|---:|---:|
| never | **0.876** | **0.500** | 0 |
| always | 0.124 | 0.500 | 1,829 |
| random | 0.539 | 0.633 | 901 |
| gap | 0.457 | 0.639 | 1,103 |

> 이 표의 분모는 **2,089** 로 위 AUC 표의 2,394 와 다르다. 정답보다 최대 2초 먼저
> 답한 것(조기 예측 인정)은 이진 집계에서 빠지기 때문이다 — 305개. AUC 는 그 구간도
> 포함해 계산한다.

**아무것도 안 하고 87.6% 를 맞힌다.** 대부분의 구간에 실제로 사고가 없으니까.
그러니 어떤 방법이 정확도 0.85 를 냈다면 **"아무 말도 안 하기"보다 못한 것**이다.

`always` 는 반대 함정이다 — 무조건 "사고 남"이라 하면 놓치는 게 0 이라(재현율 1.000)
F1 점수가 공짜로 높게 나온다.

그래서 **균형정확도 (balanced accuracy)** 를 쓴다.

```
균형정확도 = (사고를 사고라 맞힌 비율 + 무사고를 무사고라 맞힌 비율) ÷ 2

never   → (0.0 + 1.0) ÷ 2 = 0.5     ← 정보 없음이 정직하게 드러난다
always  → (1.0 + 0.0) ÷ 2 = 0.5
```

이 기준으로 보면 전체 평균에서 `gap` 은 0.639 로 초라하지만, **k=1 만 놓고 보면
0.803** 이다. 전체가 낮은 것은 답할 수 없는 구간이 끌어내린 결과다.

같은 이유로 **임계값을 F1 으로 고르면 안 된다.** F1 최대화가 재현율 쪽으로 끌려가
train 에서 사고를 154개 맞히는 대신 오탐 1,644개를 내는 값을 뽑는다. 기본을
균형정확도로 바꿨다.

## 위치를 직접 재느냐 짐작하느냐 — 인지 (perception)

**인지**는 "지금 뭐가 어디 있나"를 알아내는 단계다. 두 가지로 돌려 비교했다.

| 방식 | 뜻 | 위치 오차 |
|---|---|---|
| `sensor3d` | 데이터셋이 준 **정답 위치를 그대로** 쓴다 | 0m |
| `camera` | 화면 속 상자 하나로 위치를 **되짚는다** | 중앙값 **2.3m** |

`camera` 는 이런 방식이다 — 영상에서 차가 화면 아래쪽에 크게 보이면 가깝고, 지평선
근처에 작게 보이면 멀다. 바닥이 평평하다고 보고 삼각비로 거리를 푼다. 당연히 부정확하다.

| 구간 | sensor3d | camera | 잃은 양 |
|---:|---:|---:|---:|
| **k=1** | **0.813** | **0.575** | **−0.238** |
| k=2 | 0.622 | 0.543 | −0.079 |
| k=3 | 0.536 | 0.521 | — |
| k=4·k=5 | 0.47 | 0.50 | 둘 다 우연 수준 |

**답할 수 있는 유일한 구간이 위치 오차에 가장 취약하다.** 0.813 은 쓸 만한 판정이고
0.575 는 거의 찍는 것이다.

이 비교가 제대로 됐다는 검증 — `never`·`always`·`random` 은 위치를 쓰지 않으므로
두 방식에서 **값이 완전히 같다**. `gap` 만 변한다.

> 이 결과는 vlm 의 결론과 **갈린다.** vlm 은 "인지 개선은 거의 소진됐다"고 했지만
> 그건 LiDAR 를 쓸 때 얘기였다. **카메라로 위치를 짐작하면 인지가 벽이다.**

## 그래서 어떻게 보고하는가

**5초를 그대로 유지하되 구간별로 나눠서 낸다.** 전체 평균은 답할 수 있는 구간과
없는 구간을 섞은 값이라 해석되지 않는다.

`examples/baselines_accident_qa.py` 는 실행 끝에 구간별 표를 자동으로 찍고,
`examples/analyze_records.py` 가 저장된 기록에서 다시 계산하지 않고 같은 분해를 낸다.

**딸려 나오는 것** — 이 결과는 기존 LLM 실험의 해석도 바꾼다. 구간 5개 중 3개가
애초에 정보가 없으므로, 그 위에서 잰 예측기 비교가 잡음에 묻힌 것은 당연하다
([03 · LLM 은 같은 입력에 다르게 답한다](03-method-notes.md)).
