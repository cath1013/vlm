# 무엇이 성능을 올리는가

**질문** — 옆 프로젝트(`~/vlm`)에서 LLM 에게 기하 표를 주고 판단시킨 조건은 전부
정확도 **0.728** 에서 멈췄다. 그 값은 **같은 표에 임계값 하나를 건 것과 정확히
같다** — 즉 LLM 이 산술 이상으로 뽑아낸 것이 없었다. 그 천장은 무엇 때문이고,
`traffic_llm` 이 가진 것 중 무엇이 그것을 미는가?

**답** — 미는 것은 **앞으로 어디 갈지 찍는 정확도 하나뿐**이다. 장면 설명을 더 주는
것은 — 그것이 지도에 맞춘 정확한 수치이더라도 — **정확도를 떨어뜨린다**. 위치를
누가 알아냈느냐를 바꾸는 것은 소수점까지 **아무 효과가 없다**.

---

## 이 실험의 과제는 [01](01-prediction-horizon.md) 과 다르다

```
01 의 과제   창 하나 → 미래 5초를 1초씩 5구간, 구간마다 답
이 실험      시나리오 하나 → 앞으로 1.0초 안에 충돌하는가, 답 하나
```

`gemini-2.5-flash`, val **103** 시나리오(사고 51 / 무사고 52).
[01](01-prediction-horizon.md) 은 val **104** 개를 쓴다 — 차이는 시나리오 하나
(`Town10HD_…_scenario00034`, 무사고)뿐이지만 **판정 단위가 다르므로 두 보고서의
절대값을 가로질러 비교하면 안 된다.**

## 출발점 — 이전 결과

vlm 은 중앙 모델에게 무엇을 주느냐로 여섯 조건을 돌렸다. 요약하면 둘이다.

- **관측자가 쓴 산문을 주면 나빠진다** — 각 센서가 LLM 으로 쓴 "1번과 2번이 수렴 중,
  위험 높음" 같은 글. 세 조건 모두 0.53~0.64 로, 기하 표만 준 것보다 낮았다.
- **숫자를 주면 0.728 에서 멈춘다** — 그리고 그 값은 **같은 표의 최솟값에 임계값 하나를
  건 것과 정확히 같다.** LLM 이 산술 이상으로 뽑아낸 것이 없었다는 뜻이다.

vlm 은 이 천장의 원인을 스스로 지목했다:

> 인지 개선은 거의 소진됐다. **0.76~0.80 의 벽은 예측 모델 — 1초 등속 연장 —
> 이지 센싱이 아니다.**

풀어 쓰면 이렇다. 표를 만들 때 "차가 지금 속도로 계속 직진한다"고 가정했는데,
**실제로는 돌고 서고 양보한다.** 그 가정이 틀린 만큼 표가 틀리고, LLM 은 틀린 표
이상을 낼 수 없다.

`traffic_llm` 에는 그 가정을 대신할 것이 있다 — **WaypointNet**. 이 프로젝트를 위해
직접 만들고 학습시킨 신경망이다(DeepAccident 논문의 V2XFormer 와는 무관하다).
15만 표본으로 학습해 "이 차는 1초 뒤 여기, 2초 뒤 여기"를 직접 찍는다.

| 시험셋 23,453 표본 | 평균 오차 (ADE) | 마지막 점 오차 (FDE) |
|---|---:|---:|
| **WaypointNet** | **3.01 m** | **5.25 m** |
| 지도 규칙 기반 | 4.01 | 7.00 |
| 등속 직진 | 4.13 | 7.42 |

## 실험 — 한 번에 하나씩만 바꾼다

시나리오·시점·응답 형식·모델을 전부 고정하고, **딱 한 군데씩** 바꿔서 아홉 번 돌렸다.

| | 모델이 받은 것 | 정확도 | 정밀도 | 오탐 | 클래스쌍 |
|---|---|---:|---:|---:|---:|
| *이전 천장* | 기하 표만 (**등속**) | 0.728 | 0.795 | 8 | 0.032 |
| | 기하 표 + 조감도 이미지 | 0.728 | 0.767 | 10 | **0.606** |
| *이전 최고* | 프로덕션 — 표 + 이미지, 호출 1회 | 0.738 | 0.761 | 11 | 0.629 |
| **시도 ①** | + iitp 장면 설명 *(세 판)* | 0.631~0.670 | 0.59~0.61 | **28~31** | 0.34~0.39 |
| **시도 ②** | iitp 가 만든 표 (**등속**) | 0.728 | 0.756 | 11 | 0.500 |
| **시도 ③** | iitp 가 만든 표 (**WaypointNet**) | **0.786** | **0.854** | **6** | 0.486 |
| **최종** | ③ + 조감도 이미지 | 0.777 | 0.804 | 9 | **0.649** |

시도 ① 은 세 번 돌렸다 — 장면 설명 전체(0.631), 판정 라벨을 뺀 것(0.660),
거기에 이미지를 더한 것(0.670). **세 판 모두 이전 천장 아래**다.

용어: **정밀도 (precision)** = "사고"라 한 것 중 진짜 비율. **재현율 (recall)** = 진짜
사고 중 잡아낸 비율. **오탐 (false positive)** = 아닌데 사고라 한 횟수.
**클래스쌍** = 부딪히는 두 차의 종류(car/van 등)를 맞혔는가.

## ① 설명을 더 주면 나빠진다 — 세 번 확인했다

iitp 의 장면 설명에는 vlm 이 한 번도 받아본 적 없는 것이 들어 있다: 어느 도로 몇 차선,
다음 교차로까지 몇 m, 제한속도, 가속도 수치, 예상 경로, 그리고 충돌까지 남은
시간(TTC)·차간 시간(headway)·교차로 도달 시간차가 붙은 상호작용 목록. **전부 사람이
아니라 결정론적 코드가 계산한 값이다.**

```
G  설명 전체 (중앙값 20,606자)   0.728 → 0.631   오탐  8 → 31
H  판정 라벨 7,057개 제거         0.660           오탐 28   ← 30% 만 회복
J  이미지까지 추가                0.670           오탐 29   ← 거의 그대로
```

**원인은 라벨이 아니다.** `keeping lane`(차선 유지), `orthogonal entry conflict
expected`(직교 진입 상충 예상) 같은 **판정 성격의 말**을 전부 걷어내고 숫자를 97.8%
남겨도 오탐이 31 → 28 로 3건 줄 뿐이다. 이미지를 더해도 마찬가지다.

**설명이 있으면 이미지를 못 쓴다.** 설명이 없을 때 이미지는 클래스쌍 식별을
0.032 → 0.606 으로 끌어올린다(E → F). 설명이 있으면 같은 이미지가 0.341 → 0.391
밖에 못 만든다(H → J). **효과가 1/11 로 줄었다.**

재현율만 계속 오른다 — 0.608 → 0.863 → 0.902, 놓친 사고가 20 → 7 → 5 로 준다.
그러나 오탐이 훨씬 빨리 늘어난다. vlm 이 A → B → C 에서 본 것 그대로다:

> 모델은 모든 입력을 **위험의 증거로만** 취급하고, 위험하지 않다는 증거로는 결코
> 취급하지 않는다.

차 20대 안팎의 상태를 전부 나열하면 위험해 보이는 조합이 반드시 생기고, 모델은
그것을 센다.

## ② 위치를 누가 알아냈느냐는 무효

**등속 판**은 표를 vlm 의 LiDAR 덩어리가 아니라 **iitp 가 다섯 관측자를 합쳐 확정한
차량 목록**으로 다시 계산한 것이다. 앞으로 미는 방식은 등속 그대로다.

```
vlm 의 LiDAR 덩어리로 만든 표      0.728
iitp 의 확정 차량 목록으로 만든 표   0.728    ← 소수점까지 같다
```

vlm 의 진단("센싱이 아니다")이 여기서 직접 확인된다.

## ③ 앞으로 어디 갈지 찍는 정확도만 효과가 있다

**등속 판**과 **WaypointNet 판**은 **차량 목록·좌표계·시점이 전부 같고, 앞으로 미는 방식만 다르다.**

```
등속        (지금 속도로 직진)      정확도 0.728   정밀도 0.756   오탐 11
WaypointNet (학습된 궤적)         정확도 0.786   정밀도 0.854   오탐  6
                                  ──────         ──────        ──────
                                  +0.058         +0.098        절반 이하
```

재현율을 정밀도와 맞바꾼 것이 아니다 — **양쪽 다 올랐다**(재현율 0.667 → 0.686).
①에서 본 "재현율↑ 정밀도↓" 와 정반대 방향이다.

### 크기가 다른 실험에서도 같게 나온다

같은 교체를 [01](01-prediction-horizon.md) 의 과제(5초를 1초씩 5구간)에서 했을 때:

| 구간 | 등속 | WaypointNet |
|---:|---:|---:|
| **k=1** | 0.813 | **0.871** |
| k=2 | 0.622 | 0.617 |
| k=3 | 0.536 | 0.564 |

```
01 의 과제 (AUC)      0.813 → 0.871   +0.058
이 실험    (정확도)    0.728 → 0.786   +0.058
```

**과제도 지표도 다른데 크기가 같다.**

### 다만 예측 범위 (horizon) 는 늘어나지 않는다

k=2 는 −0.005, k=4·k=5 는 여전히 우연 수준이다. **더 나은 예측기는 답할 수 있는
구간을 더 잘 풀 뿐, 답할 수 없는 구간을 답할 수 있게 만들지 못한다.**
2초 벽은 예측 품질의 문제가 아니라 과제 자체의 성질이다([01](01-prediction-horizon.md)).

## 탐지 (detection) 와 식별 (identification) 은 서로 다른 입력에서 온다

**탐지** = 충돌이 일어나는가. **식별** = 누가 부딪히는가.

| | 탐지 (정확도) | 식별 (클래스쌍) |
|---|---:|---:|
| 기하 표만 (등속) | 0.728 | 0.032 |
| 기하 표 + 이미지 | 0.728 | **0.606** |
| iitp 표 (WaypointNet) | **0.786** | 0.486 |
| **iitp 표 (WaypointNet) + 이미지** | 0.777 | **0.649** |

**표는 탐지를, 이미지는 식별을 만든다.** 둘을 같이 준 **최종 구성**이 이전 최고를 전 항목에서 이긴다:

```
            정확도    F1    클래스쌍   오탐   미탐
이전 최고    0.738  0.722    0.629     11    16
최종        0.777  0.763    0.649      9    14
```

맞바꾼 것이 하나도 없다. 목적에 따라 **오탐을 최소로 하려면 이미지 없이**(6건), **균형과 식별을 함께 보려면 이미지까지**.

## 남는 것

- **충돌 유형·방향·충격 부위는 여전히 우연 수준**이다(둘 다 "사고"라 답한 35~37건
  기준이라 표본도 작다). 개선된 것은 탐지와 클래스쌍뿐이다.
- **같은 조건을 두 번 돌려보지 않았다.** [03 · LLM 은 같은 입력에 다르게 답한다](03-method-notes.md) 참조.
- WaypointNet 표에서 **판정을 좌우하는 항목은 거의 안 움직였다** — 쌍의 39.5% 가 값이
  바뀌는데 "간격 0.00m"인 쌍은 63 → 61 이다. 이득이 정확히 어디서 왔는지는 아직
  분해되지 않았다.

## 재현

```bash
# iitp 표 내보내기 (등속·WaypointNet 두 판)
.venv/bin/python examples/export_gaptable_for_vlm.py \
    --root /home/sryu/inclab-nas/DeepAccident --carla-maps ./carla_map \
    --split val --horizon 1.0 --out out/vlm_scene/gaps_val_h1.0.json

# vlm 조건에 끼워 넣기 — 두 판을 다 돌려야 인지와 예측기가 분해된다
cd ~/vlm && source /home/sryu/inclab-nas/sryu/iitp/env.sh
for V in cv predicted; do
  .venv-vlm/bin/python scripts/add_condition.py \
      --condition K_iitp_geometry_only --label "K_iitp_$V" \
      --iitp-gaps .../gaps_val_h1.0.json --gap-variant "$V" \
      --model gemini-2.5-flash
done
```
