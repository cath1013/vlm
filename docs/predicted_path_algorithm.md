# `PredictedPath` 생성 알고리즘

payload 의 `predicted_paths`(자연어에서는 `예상경로: …`)가 어떻게 만들어지는지를
**기동 판별 · 확률 산정 · 좌표 생성** 세 축으로 설명한다. 값이 어떤 식에서 나오고
왜 그렇게 정했는지, 그리고 무엇을 뜻하지 **않는지**까지 적는다.

책임이 두 모듈에 나뉘어 있다.

| 모듈 | 하는 일 |
|---|---|
| `roadmap.downstream_paths()` | **기동 라벨**과 **확률**을 정하고 도로 폴리라인을 만든다 |
| `prediction.build_context()` | 후보를 만들어 `PredictContext` 로 모은다. 버려진 후보가 있으면 확률을 재정규화한다 (§5.4) |
| `prediction.rule_predict()` | 폴리라인을 **시간축 웨이포인트**로 바꾸고, 중복을 합치고, 예외를 처리한다 |
| `prediction.predict()` | 예측기를 고르는 진입점일 뿐이다 — 기본은 `rule_predict`, 학습 모델을 끼우면 그것을 부른다 |

---

## 0. 전체 순서

```
ActorState (위치·속도·방위·RoadPlacement)
   │
   ▼  ⓪ 후보 생성 + 확률 재정규화        prediction.build_context
   │
   ▼  ① 예외 분기                       prediction.rule_predict
   ├─ 속도 미확정            → "속도 미확정 — 경로 예측 보류"   (끝)
   ├─ 속도 < 0.5 m/s        → "정지 유지"                    (끝)
   └─ 도로 미매칭            → "등속 직진(지도 미매칭)"        (끝)
   │
   ▼  ② 지평 거리 계산                   predict
   horizon_m = 속도 × horizon_s
   │
   ▼  ③ 현재 도로를 따라 샘플링           roadmap.downstream_paths
   along  (진행 방향 판정 → 차로 오프셋 적용 → 5m 간격)
   │
   ▼  ④ 교차로 도달 판정
   ├─ 남은 거리 ≤ 5m  또는 교차로 없음  → ("직진", 1.0) 하나  (끝)
   └─ 교차로 도달
   │
   ▼  ⑤ 진출로별 기동 분류 + 기본 가중치
   ▼  ⑥ 차선 위치로 가중치 보정
   ▼  ⑦ 정규화 (기동 단위 → 진출로 수로 분배)
   │
   ▼  ⑧ 시간축 재샘플링                  prediction._resample_by_time
   ▼  ⑨ 동일 기하 병합                   prediction.merge_identical
   PredictedPath[]  (maneuver, probability, waypoints, to_roads, truncated)
```

## 1. 예외 분기 — 무엇을 예측하지 않는가

`rule_predict()` 의 첫 세 갈래는 **경로를 만들지 않는다**. 각각 다른 이유가 있고,
라벨로 그 이유를 구별한다.

| 조건 | 라벨 | 확률 | 웨이포인트 |
|---|---|---|---|
| `speed_mps is None` | `속도 미확정 — 경로 예측 보류` | 1.0 | 현재 위치 1개 |
| `speed < 0.5 m/s` | `정지 유지` | 1.0 | 현재 위치 1개 |
| `placement is None`, 방위 있음 | `등속 직진(지도 미매칭)` | 1.0 | 방위 방향 등속 외삽 |
| `placement is None`, 방위 없음 | `불확실` | 1.0 | 현재 위치 1개 |

> **`속도 미확정` 과 `정지 유지` 를 반드시 구별한다.** 추적 이력이 짧아 속도를
> 판정하지 못한 차량을 "정지"로 쓰면 **움직이는 차를 멈춰 있다고 보고**한다.
> 최소자승 속도 적합은 2Hz 에서 표본 4개(1.5초)가 필요하므로, 새로 관측된 차량과
> 누적 창의 앞부분(`0-1` 등)에서 이 라벨이 자주 나온다.

`0.5 m/s` 는 정지 판정선이다. 그 아래는 위치 잡음과 구별되지 않는다.

**등속 외삽**(`_constant_velocity`)은 도로를 못 찾았을 때만 쓴다.

```
점_k = 현재위치 + 방위단위벡터 × 속도 × k      (k = 0, 1, …, ⌊horizon_s⌋)
```

지도 제약이 없으므로 인도를 걷는 보행자나 주차장 차량이 여기로 온다. 노면을 벗어나
뻗기 때문에 BEV 에서는 이 경로를 그리지 않는다.

---

## 2. 지평 거리 — 확률이 아니라 거리로 자른다

```
horizon_m = speed_mps × horizon_s
```

`horizon_s` 는 `PipelineConfig.prediction_horizon_s`(**기본 5초**)다. 질문의 예측
지평(`WindowConfig.horizon_s`, 기본 5초)과 우연히 같은 값이지만 **별개 설정**이다 —
경로는 "곧 어디로 가는가"를 보이는 보조 정보이고, 질문은 구간별 사고 여부를 묻는다.

속도에 비례하므로 빠른 차량은 더 멀리, 느린 차량은 짧게 본다. 실측 예:
보행자 3.3m/s → 지평 16.5m, 차량 2.4m/s → 11.8m.

## 3. 현재 도로 따라가기 (`along`)

### 3.1 진행 방향 판정

```python
axis    = placement.axis_bearing_deg          # 차량이 있는 지점의 도로축
reverse = abs(wrap180(placement.bearing_deg - axis)) > 90.0
```

`axis_bearing_deg` 는 `locate()` 가 저장한 **국소** 도로축이다.

> **폴리라인 첫 구간과 비교하면 안 된다.** 곡선 도로에서 차량이 s 축을 따라 멀리
> 있으면 국소 방위가 첫 구간과 90° 넘게 달라 판정이 뒤집힌다 — 실측으로 **22% 의
> 경로가 방위와 180° 반대**로 나갔다. 국소 축을 쓰도록 고친 뒤 2% 로 줄었고, 남은
> 것은 교차로에 붙은 차량의 유턴·급회전(기하적으로 정상)뿐이다.

### 3.2 차로 오프셋 적용

중심선이 아니라 **차량이 달리는 차로**를 따라간다.

```python
lat = placement.lateral_offset_m              # 진행 방향 기준 좌(+)/우(−)
along = _sample_along(road, s_m, horizon_m, reverse, lat)
```

`_sample_along` 은 5m 간격으로 `road.point_at(s)` 를 뽑고, 각 점을 그 지점 도로축의
**좌측 법선** 방향으로 `lat` 만큼 평행이동한다.

```
진행방위 brg → 전방단위 (sin brg, cos brg) → 좌측법선 (−cos brg, sin brg)
점 = point_at(s) + 좌측법선 × lat
```

> 중심선을 그대로 쓰면 첫 웨이포인트가 현재 위치에서 **차로 폭만큼**(실측 5~10m)
> 떨어져, 경로가 엉뚱한 곳에서 출발하는 것처럼 보인다. 모델이 실제로
> "e≈29.8 로 스냅된다"고 지적한 값이 도로 중심선이었다.

### 3.3 교차로 도달 판정

```python
remaining = horizon_m - poly_len(along)
if remaining <= 5.0 or next_junction_id is None:
    return [("직진", 1.0, along, road.name)]
```

지평 안에 교차로가 들어오지 않으면 **분기가 없으므로 `직진` 하나**다. 실측 분포에서
액터의 **307건 중 대부분**이 이 경로다(단일 `직진`).

교차로가 있어도 `Junction.is_intersection` 이 False 면(도로 2개만 만나는 단순 연결)
분기가 아니므로 역시 `직진` 하나다.

## 4. 기동 판별 — 진출 방위차로만 정한다

교차로에서 나가는 도로마다 **진출 방위**를 재고, 현재 진행 방위와의 차이로 기동을
분류한다.

```python
out_reverse = nxt.node_end == junction_id      # 교차로가 그 도로의 끝점이면 역방향 진출
out_bearing = nxt.bearing_at(끝 구간 if out_reverse else 0)
if out_reverse:
    out_bearing = (out_bearing + 180) % 360     # 진출 방향으로 뒤집는다
turn = wrap180(out_bearing - placement.bearing_deg)   # −180 ~ +180
```

| `turn` 범위 | 기동 | 기본 가중치 |
|---|---|---|
| \|turn\| < 30° | `직진` | **0.60** |
| \|turn\| > 150° | `유턴` | **0.02** |
| turn > 0 (30~150°) | `우회전` | **0.20** |
| turn < 0 (−150~−30°) | `좌회전` | **0.20** |

판정 순서가 중요하다 — `유턴` 을 좌/우보다 **먼저** 본다. 그러지 않으면 `turn=+170°`
가 `우회전` 으로 분류된다.

### 부호 규약 — 양수는 우회전이다

방위각은 **진북 기준 시계방향**이다 (북 0°, 동 90°, 남 180°, 서 270°).
따라서 방위가 커지는 것은 시계방향이고, 그것이 차량 기준 **우회전**이다.

```
북행(0°) 차량이 동행(90°) 으로 나간다 → turn = +90° → 우회전
전방벡터 (0,1) × 이동벡터 (1,0) 의 z = 0·0 − 1·1 = −1 < 0  (우측)
```

> **이 부호가 반대로 쓰여 있었고**, 실데이터에서 좌/우 라벨 **41건이 뒤집혀**
> 있었다. 기존 테스트가 "세 라벨이 모두 나오는지"와 "1차선이 좌회전에 유리한지"만
> 봤기 때문에 잡히지 않았다 — 라벨을 서로 바꿔도 두 검사는 통과한다.
> 지금은 경로 마지막 구간의 방위와 라벨이 일치하는지를 네 방위 모두에서
> 검사한다(`TestTurnLabelConvention`).

> **이것은 지도 기하만 쓴다.** 방향지시등·제동등·차선 표시(직진전용/좌회전전용)를
> 보지 않는다. 데이터에 없기 때문이다.

### 실측 예 1 — 좌/우 분기

```
P004 · Road 2065 방위 5°(거의 북행) · 교차로 J37 까지 18m
  Road 20     방위차 +87.6° → 우회전  기본 0.20     (동쪽으로 나감)
  Road 2071   방위차 −88.8° → 좌회전  기본 0.20     (서쪽으로 나감)
```

### 실측 예 2 — 유턴이 섞인 경우

```
EGO_other_vehicle_behind · Road 2370 방위 357° · 교차로 J48 도달
  Road 2353   방위차 −173.2° → 유턴   기본 0.02
  Road 2358   방위차 −175.9° → 유턴   기본 0.02
  Road 2363   방위차 −177.5° → 유턴   기본 0.02
  Road 27     방위차   +3.3° → 직진   기본 0.60
```

CARLA 교차로가 한 방향에 연결로를 여럿 열어 두어 `유턴` 후보가 3개 나왔다.

## 5. 확률 산정 — 세 단계

### 5.1 기본 가중치 (사전확률)

위 표의 `0.60 / 0.20 / 0.20 / 0.02` 다. **도로 구조에서 유도한 사전확률**이며 관측된
의도가 아니다. 직진이 회전보다 3배, 유턴은 사실상 무시할 수준으로 둔다.

### 5.2 차선 위치 보정

```python
from_median = lane_index if numbering == "from_median" else lane_count - lane_index + 1
if 기동 == "좌회전":  w *= 2.0 if from_median == 1        else 0.4
if 기동 == "우회전":  w *= 2.0 if from_median == lane_count else 0.4
```

- **1차선(중앙선쪽)** 에 있으면 좌회전 ×2.0, 아니면 ×0.4
- **최외측 차선**에 있으면 우회전 ×2.0, 아니면 ×0.4
- `직진`·`유턴` 은 보정하지 않는다
- 차선이 미확정이거나 단일 차선(`lane_count == 1`)이면 보정 없음

차로에서 회전하려면 미리 그 차선으로 옮겨야 하므로, 차선 위치가 회전 의도의 **유일한
관측 가능한 단서**다.

### 5.3 정규화 — 기동 단위로 나눈다

```python
by_label[기동] = 보정된 가중치            # 같은 기동은 같은 가중치
n_by_label[기동] = 그 기동의 진출로 수
total = sum(by_label.values())

확률 = by_label[기동] / total / n_by_label[기동]
```

**확률은 기동 단위의 사전확률이고, 그 몫을 진출로 수로 나눈다.**

> 진출로마다 독립적으로 가중치를 주면, 교차로가 오른쪽 진출로를 2개 열어 두었다는
> 이유만으로 우회전이 좌회전의 2배가 된다. 지도 배치가 확률을 왜곡하면 안 된다.

### 5.4 버려진 후보의 확률은 재분배한다

`build_context()` 는 폴리라인이 점 1개뿐인 후보를 버린다 (경로를 만들 수 없다). 그러면
`downstream_paths` 가 그 후보에 준 확률이 사라지고, 규칙 기반은 `prior` 를 **그대로**
확률로 쓰므로 합이 1 미만이 된다.

```python
total = sum(c.prior for c in cands)
if cands and total > 0 and abs(total - 1.0) > 1e-9:
    for c in cands:
        c.prior /= total
```

고치기 전 실측으로 전체의 **0.015%**(151,563 중 22건)에서 합이 1 이 아니었고, 최악은
**0.032** 였다 — payload 가 "직진 3%" 만 내보내 읽는 쪽이 "어디로도 가지 않는다"로
해석하게 된다. 재정규화는 균일 배율이므로 **후보 순위를 바꾸지 않는다**(베이스라인 불변).

회귀 테스트: `tests/test_pipeline.py::TestPluggablePredictor` 의
`test_dropped_candidates_do_not_leak_probability` · `test_renormalization_preserves_ranking`.

### 실측 계산 검증

**예 1** — 좌회전 1개 + 우회전 1개, 단일 차선(보정 없음):

```
by_label = {우회전: 0.20, 좌회전: 0.20},  total = 0.400,  개수 = {1, 1}
우회전 = 0.20 / 0.400 / 1 = 0.5000
좌회전 = 0.20 / 0.400 / 1 = 0.5000
```

**예 2** — 직진 1개 + 유턴 3개:

```
by_label = {유턴: 0.02, 직진: 0.60},  total = 0.620,  개수 = {유턴: 3, 직진: 1}
직진 = 0.60 / 0.620 / 1 = 0.9677
유턴 = 0.02 / 0.620 / 3 = 0.0108   (× 3개 = 0.0323)
```

합 = 0.9677 + 0.0108×3 = **1.0000** ✓

### 5.5 표시 반올림

직렬화 시점에 소수 2자리로 줄이되 **최대잉여법**으로 표시값 합을 1.00 에 맞춘다
(`serialize._round_probs`). 각각 독립으로 반올림하면 `0.3417 × 3 = 1.02` 처럼
합이 어긋나고, 그러면 확률 자체를 못 믿게 된다.

## 6. 좌표 생성 — 시간축 재샘플링

폴리라인은 **5m 등간격**(거리 기준)이고, payload 의 웨이포인트는 **1초 등간격**
(시간 기준)이다. `_resample_by_time` 이 변환한다.

```python
누적거리 cum[i] = 폴리라인 시작부터 i번째 정점까지의 호길이
k = 0, 1, 2, …  (dt = 1초)
    target = 속도 × k                        # 현재 속도 유지 가정
    target 이 속한 구간 j 를 찾아 선형보간
    점_k = poly[j] + r × (poly[j+1] − poly[j])
```

### 6.1 경로는 차량 위치에서 시작한다

```python
if dist(actor.world_xy, poly[0]) > 0.5:
    poly = [actor.world_xy] + poly
```

도로 샘플링은 `s[m]` 지점의 좌표를 쓰므로 곡선 구간이나 도로 밖(보행자)에서는 첫 점이
실제 위치와 몇 m 떨어진다. 실제 위치를 앞에 붙여 **첫 웨이포인트를 정확히 일치**
시킨다 (실측: 0.5m 초과 이탈 30% → 0%).

### 6.2 도로망 끝에서 잘림 (`truncated`)

```python
if target > total:            # 폴리라인이 지평보다 짧다
    truncated = True
    끝점을 한 번만 찍고 중단
```

> 예전에는 남은 시각을 **마지막 점으로 채웠다.** 그러면 같은 좌표가 반복되어
> "그 자리에 정지한다"는 예측으로 읽힌다. 실제 의미는 "이 앞은 도로망이 없어 예측할
> 수 없다"이므로, **짧은 목록 + `truncated=True`** 로 알린다.

웨이포인트 개수가 곧 예측이 닿은 시간이다 — 6개면 0~5초, 4개면 0~3초에서 잘렸다.

### 6.3 출력 해상도

직렬화에서 **0.1m** 로 반올림한다. 1m 로 뭉개면 차로 폭(3.5m)의 30% 라 좌표가 같은
값으로 뭉쳐 회전 궤적이 계단처럼 보인다.

## 7. 동일 기하 병합 (`merge_identical`)

```python
key = (기동, 웨이포인트를 0.1m 로 반올림한 tuple)
같은 key → 확률을 더하고, to_roads 를 합치고, truncated 는 OR
```

CARLA 는 한 도로를 차로마다 별개 `road` 로 쪼개므로, 합치지 않으면 **라벨·확률·좌표가
똑같은 항목이 여러 개** 나간다. 실제로 `우회전 0.33 / 우회전 0.33 / 우회전 0.33` 이
좌표까지 동일하게 나왔고, 모델이 이를 근거 불확실 사유로 지적했다.

비교 기준을 **출력 해상도(0.1m)** 로 잡는 이유: 그보다 미세한 차이는 payload 에
나타나지 않으므로 다른 경로라고 부를 근거가 없다.

병합 후 확률 내림차순으로 정렬한다. 자연어 브리핑은 상위 3개만 싣는다.

> `roadmap` 단계에도 중복 제거가 한 번 있다(`seen_geom`, 0.01m 기준, 폴리라인
> 대상). 그것은 **샘플링 단계**의 완전 중복을 걸러내고, `merge_identical` 은
> **재샘플링 후 출력 해상도**에서 같아진 것을 합친다. 둘의 기준이 다르므로 둘 다
> 필요하다.

## 9. 이 값이 뜻하지 않는 것

- **회전 의도가 아니다.** 방향지시등·제동등·운전자 시선을 관측하지 않는다.
  확률 50% 의 좌회전은 "이 차가 좌회전한다"는 근거가 아니라 "지도상 좌회전이
  가능하고 차선 위치가 그것을 배제하지 않는다"는 뜻이다.
- **동역학을 반영하지 않는다.** 현재 속도가 유지된다고 가정한다. 가감속·조향
  한계·선행차 제약이 들어가지 않는다.
- **신호를 반영하지 않는다.** 데이터에 신호등 상태·정지선·차선 표시가 없다.
  적색에 정지할 것이라는 예측을 만들 수 없다.
- **`truncated` 는 정지가 아니다.** 도로망이 끊긴 지점까지만 예측했다는 표시다.
- **차선 변경을 예측하지 않는다.** 후보는 현재 차로를 따라가는 것뿐이다
  (차선 변경은 관측된 기동 라벨로만 나타난다).

정확도를 올리려면 신호 상태와 차선 표시 종류(직진전용/좌회전전용)를 지도에 추가하는
것이 가장 효과가 크다 — 지금은 그 둘이 없어 사전확률에 의존한다.
