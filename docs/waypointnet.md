# WaypointNet — 좌표를 직접 내는 경로 예측 모델

`traffic_llm/predict_nets.py` 의 `WaypointNet` 구조와 각 설계 판단의 근거를 적는다.
입출력 계약 자체는 [`predict_model_io.md`](predict_model_io.md) 에 있고, 여기서는
**모델 내부**를 다룬다.

---

## 1. 왜 이 모델이 있는가

기본 예측기(`rule_predict`)와 `RankNet` 은 **지도가 낸 후보 중 하나를 고른다.** 그래서
후보 집합에 정답이 없으면 절대 맞힐 수 없는데, 실측으로 그런 경우가 **21.4%** 다
(차선 변경·노면 이탈·급감속). 후보 방식의 정확도 상한이 78.8% 로 막혀 있다는 뜻이다
([predict_model_io.md §4.1 · §5.6](predict_model_io.md)).

`WaypointNet` 은 후보를 고르지 않고 **미래 좌표를 회귀한다.** 상한이 없다.

| 시험셋 (23,453) | ADE | FDE |
|---|---:|---:|
| **WaypointNet** (이력 트랜스포머, 기본) | **3.01 m** | **5.25 m** |
| WaypointNet (이력 없음) | 3.05 m | 5.30 m |
| 규칙 기반 (top-1 후보) | 4.01 m | 7.00 m |
| 등속 직진 | 4.13 m | 7.42 m |
| 후보 최선 = 후보 방식의 오라클 | 3.75 m | — |

후보를 완벽히 골라도 3.75m 인데 3.01m 다 — 상한을 실제로 넘었다.
과거 궤적을 쓰면 3.05 → 3.01m 로 조금 더 낫다 (§2.5).

## 2. 전체 구조

```
입력                                                             파라미터
  g  [22]  또는 [B, 22]          액터·도로 상태
  c  [N,12] 또는 [B, N, 12]      후보 경로 N개 (N 은 표본마다 다름)
  h  [5,5] 또는 [B, 5, 5]        과거 5초 궤적 (1초 간격, 마지막 칸이 valid)
     │
     ├─ HistoryEncoder(h) → [B,64] + 이력있음 1칸    트랜스포머 기본      34,176
     │
     ├─ candidate_mask(c) = c[...,0] > 0        패딩 판정 (정규화 전!)
     ├─ constant_velocity(g)  → cv [B,K,2]      등속 기준선 (원 눈금에서)
     │
     ▼ _norm(g, c)                              학습셋 통계로 표준화
  gn [B,22]      cn [B,N,12] (패딩 자리 다시 0)
     │
     ▼ cand_enc: Linear(12→128) ReLU Linear(128→128) ReLU        18,176
  ch [B, N, 128]                                후보별 인코딩 (이력 `h` 와 이름을
                                                겹치면 안 된다 — 실제로 터졌다)
     │
     ├─ attn: Linear(128→1) → softmax(마스킹)   → 어텐션 가중합       129
     ├─ 마스킹 평균
     └─ 마스킹 최대
     ▼ concat
  pooled [B, 384]                               후보 집합의 순서 무관 요약
     │
     ▼ z = concat(gn, pooled, hist, has_history)  [B, 471]
     │
     ▼ trunk: Linear(471→128) ReLU Drop Linear(128→128) ReLU Drop  76,928
  t [B, 128]                                    **두 헤드가 공유**
     │
     ├─ wp_head:  Linear(128→K*2) → reshape [B,K,2]  (+cv)         1,290
     └─ man_head: Linear(128→5)                                      645
                                                            총 131,344
출력
  좌표      [K,2] 또는 [B,K,2]   현재 위치 기준 상대좌표, t=1..K초
  기동 로짓 [5]   또는 [B,5]     직진·좌회전·우회전·유턴·후보 밖 경로
```

기본값: `hidden=128`, `n_steps=5`(1~5초), `dropout=0.1`,
`residual=True`, `predict_maneuver=True`, `history_encoder="transformer"`.

**파라미터의 59% 가 `trunk` 에 있다** (이력 인코더 26%, 후보 인코더 14%). `trunk` 입력이
471차원(전역 22 + 후보 풀링 384 + 이력 64 + 이력있음 1)이라 첫 층이 크다. 더 줄이려면
후보 풀링을 3중에서 줄이는 것이 가장 효과가 크다.

## 2.5 과거 궤적 인코더 — 계열 구조

`ActorState.track_history` 로 들어온 과거 5초를 `HistoryEncoder` 가 고정 길이 벡터로
바꾼다 (`history` 5×5 → [B, 64]). `--history-encoder` 로 구조를 고른다.

| kind | 구조 | 파라미터(전체) |
|---|---|---:|
| `transformer` (기본) | 위치 임베딩 + self-attention 1층 + 마스킹 평균 풀링 | 131,344 |
| `gru` | 단방향 GRU, **마지막 유효 단계**의 은닉상태 | 110,800 |
| `mlp` | 평탄화 후 MLP — **순서 구조 없는 대조군** | 102,992 |
| `none` | 이력을 쓰지 않음 (예전 동작) | 88,848 |

이력 벡터와 함께 **"이력이 있었는가"를 1칸** 더 붙인다. 0 벡터만 주면 모델이 "이력 없음"과
"5초 동안 정지"를 구별할 수 없다.

> **전부 패딩인 행에서 NaN 이 났다.** transformer 의 `src_key_padding_mask` 를 모든
> 위치에 걸면 어텐션 softmax 의 분모가 0 이 되어 NaN 이 나오고, 그 NaN 이 손실 전체를
> 오염시킨다. 이력이 없는 새 트랙에서 실제로 그랬다. 그런 행은 한 자리를 열어 두고
> **출력을 0 으로 덮는다** — GRU 쪽과 같은 규약이다.
> 회귀 테스트: `tests/test_history_input.py::TestHistoryEncoderModule`.

> GRU 는 `out[:, -1]` 을 쓰지 않고 **마지막 유효 단계**를 고른다. 최근 관측이 끊긴
> 트랙에서 그냥 마지막을 쓰면 0 행을 통과한 상태를 읽는다.

### 얼마나 도움이 되는가 — 시드 3회 실측

| `--history-encoder` | 시험 ADE (시드 0/1/2) | 평균 |
|---|---|---:|
| `none` | 3.05 / 3.03 / 3.04 m | 3.040 |
| `gru` | 3.03 / 3.02 / 3.02 m | 3.023 |
| **`transformer`** | **3.01 / 2.99 / 3.01 m** | **3.003** |

시드 폭이 각 조건 안에서 0.02m 인데 `none` 과 `transformer` 의 범위가 겹치지 않는다
(3.03–3.05 대 2.99–3.01). 즉 **이득은 실재하지만 작다 — 약 0.04m(1.2%)** 다.
후보 순위에서 좌표 회귀로 바꿀 때의 이득(4.01 → 3.05, −24%)과는 규모가 다르다.

이득이 **이력 보유량을 따라간다**는 것이 기전을 뒷받침한다 (같은 시드, val 전체 기준).

| 유효 이력 단계 | 표본 | `none` | `transformer` | 차이 |
|---:|---:|---:|---:|---:|
| 0 | 1,743 | 4.03 | 4.07 | **+0.04** |
| 1 | 3,922 | 4.22 | 4.16 | −0.06 |
| 2 | 3,900 | 3.71 | 3.68 | −0.03 |
| 3 | 3,539 | 3.44 | 3.40 | −0.04 |
| 4 | 3,008 | 3.25 | 3.21 | −0.03 |
| 5 | 7,341 | 2.26 | 2.20 | −0.06 |

이력이 **0단계면 오히려 나쁘다**(+0.04) — 쓸 정보가 없는데 파라미터만 늘었다.
1단계 이상에서 일관되게 낫고 5단계에서 가장 낫다.

(이 표의 절대값은 학습 스크립트의 보고값과 다르다 — 여기서는 규칙 기반 후보와의 공통
지지 구간으로 제한하지 않고 val 전체를 썼다. **표 안의 상대 비교**만 의미가 있다.)

왜 이득이 작은가. `global` 이 이미 속도·가속도·방위를 담고 있어 1차 운동은 이미 있고,
등속 잔차가 지배적인 움직임을 이미 맞힌다. 이력이 더하는 것은 그 위의 고차 정보다.
게다가 전체 레코드의 **평균 유효 단계가 3.12/5**, 5단계를 채운 것은 34.1% 뿐이다.

## 3. 후보를 어떻게 집계하는가

후보 수 `N` 은 표본마다 다르다 (1~9). 고정 크기 벡터로 만들어야 하고, 그 방법이
성능과 함정을 동시에 만든다.

**후보를 무시하면 안 된다.** 그러면 모델이 회전을 알 수 없다 — 교차로에서 어디로 갈 수
있는지가 후보에만 들어 있다.

**순서에 의존하면 안 된다.** `c[0], c[1], …` 를 그대로 이어 붙이면 모델이 `downstream_paths`
가 후보를 내놓는 순서를 외운다. 그 순서는 도로 id 순이지 의미 있는 순서가 아니다. 같은
문제가 정답 라벨 쪽에서도 실제로 일어났다 (`label_ambiguous`, [§4.1](predict_model_io.md)).

그래서 **순서에 무관한 3중 풀링**을 쓴다.

| 풀링 | 무엇을 잡는가 |
|---|---|
| 어텐션 가중합 | "어느 후보가 중요한가" 를 학습한다. 유일하게 학습되는 풀링이다 |
| 평균 | 후보 집합 전체의 경향 (예: 전부 직진인가) |
| 최대 | 극단값의 존재 (예: 유턴 후보가 하나라도 있는가) |

셋을 이어 붙여 384차원을 만든다. 평균만 쓰면 후보가 많을 때 신호가 희석되고, 최대만
쓰면 몇 개인지를 잃는다. 어텐션만 쓰면 학습 초기에 무엇을 봐야 할지 모른다.

## 4. 등속 잔차 — 무학습 출력이 등속이다

`residual=True`(기본)면 좌표 출력이 다음과 같다.

```
좌표 = wp_head(t)  +  constant_velocity(g)
```

`constant_velocity` 는 현재 속도·방위로 만든 직선 궤적이다 (`v·k` 만큼 방위 방향으로).
그리고 **`wp_head` 의 가중치·편향을 0 으로 초기화**하므로 학습 전 출력이 **정확히
등속**이다.

왜 이렇게 하는가.

- **안전한 출발점.** 무작위 초기화로 좌표를 직접 회귀하면 초기 출력이 수십 m 를 벗어나
  손실이 크고, 거기서 내려오는 데 시간을 쓴다. 실측에서 등속 기준선 없이 학습하면
  30 epoch 동안 ADE 가 등속(4.2m)조차 넘지 못했다.
- **실패 시의 하한.** 학습이 잘 안 되면 등속 근처로 떨어진다. 노면을 벗어난 이상한
  궤적이 아니다.
- **모델은 보정만 배운다.** 가속·감속·회전이 잔차로 남으므로 배울 것이 명확하다.

> **등속이 규칙 기반보다 나은 것은 아니다.** 전체 시험셋에서 등속 4.13m, 규칙 4.01m 로
> 규칙이 약간 낫다. (개발 중 일부 조각으로 재던 시점에는 반대로 나왔고 코드 주석에
> 그렇게 적혀 있었다 — 전체 데이터로 정정했다.) 등속을 기준선으로 쓰는 이유는 성능이
> 아니라 위의 세 가지다.

`constant_velocity` 는 `g` 의 **원 눈금** 값을 쓴다 — 표준화된 `gn` 이 아니다. 속도와
방위를 실제 물리량으로 읽어야 미터 단위 궤적이 나온다. 그래서 `forward` 는 정규화보다
**먼저** `constant_velocity` 를 계산한다.

특징 위치는 `predict_model.IDX_SPEED` · `IDX_HEADING_SIN` · `IDX_HEADING_COS` 로 이름을
붙여 뒀다. 숫자를 모델 코드에 박으면 인코딩 순서를 바꿀 때 조용히 어긋난다.

## 5. 입력 표준화를 모델 안에 넣는다

특징 눈금이 크게 다르다 — 속도 0~30, 교차로 거리 0~200, 후보 길이 0~150, 원-핫 0/1.
그대로 넣으면 첫 선형층이 큰 눈금에 지배된다. **실측: 정규화 없이 30 epoch 동안 손실이
10.28 → 10.03 으로 거의 움직이지 않고 등속을 넘지 못했다.** 넣은 뒤에는 같은 조건에서
학습이 진행됐다.

평균·표준편차는 `register_buffer` 로 저장한다. 따라서

- `torch.save(model, path)` 에 **함께 실린다** → 추론 쪽에서 전처리를 따로 맞출 필요가 없다.
- `state_dict` 에 `g_mu/g_sd/c_mu/c_sd` 로 보인다.
- 옵티마이저가 건드리지 않는다 (파라미터가 아니다).

`fit_normalizer(g, c, mask)` 는 **학습셋만** 으로 부른다 (검증·시험을 보면 누출이다).
`mask` 로 패딩 후보를 뺀다 — 패딩은 0 으로 채운 자리이므로 통계에 넣으면 평균이 0 쪽으로,
표준편차가 실제보다 크게 끌려가고, 후보 수가 표본마다 달라 그 왜곡 크기도 일정하지 않다.

## 6. 패딩 마스킹 — 세 가지 주의점

`forward(g, c, h)` 계약에 **마스크 인자가 없다.** 추론 시 `TorchPredictor` 는 후보를
정확히 N개 넘기므로 마스크가 필요 없고, 학습 시에만 패딩이 생긴다. 그래서 후보 마스크는
`c` 에서, 이력 마스크는 `h` 의 `valid` 칸에서 유도한다.

```python
candidate_mask(c) = c[..., 0] > 0.0        # 0번 칸 = 사전확률
```

사전확률은 `downstream_paths` 의 가중치를 정규화한 값이라 **항상 양수**다. 패딩은 0 이므로
구별된다.

**(1) 판정을 정규화 전에 해야 한다.** 표준화하면 0 이 0 으로 남지 않으므로 `> 0` 규칙이
깨진다. `forward` 는 `candidate_mask` → `_norm` → 패딩 자리 재-0 순서로 처리한다.

**(2) `-inf` 를 쓰지 않는다.** 어텐션 softmax 와 최대 풀링 모두 `MASK_NEG = -1e9` 를 쓴다.
한 행이 전부 패딩이면 `-inf` 는 NaN 을 만들고 그 NaN 이 하류 전체를 오염시킨다. 유한한
큰 음수면 최악의 경우도 큰 음수로 끝난다. `masked_scores`(RankNet 용)도 같은 상수를 쓴다 —
같은 목적에 다른 상수를 쓰면 읽는 쪽이 다른 의도로 오해한다.

**(3) 평균 풀링의 분모를 clamp 한다.** `mask.sum(1).clamp(min=1)` — 유효 후보가 0인 행이
있으면 0으로 나눈다. 실제로는 후보가 없으면 `TorchPredictor` 가 모델을 부르지 않고
폴백하므로 발생하지 않지만, 모델을 직접 쓰는 코드를 막지는 못한다.

## 7. 두 가지 입력 모양을 모두 받는다

```
추론 (TorchPredictor):  g [22]     c [N, 12]     → [K,2],   [5]
학습 (배치, 패딩):      g [B, 22]  c [B, N, 12]  → [B,K,2], [B,5]
```

`forward` 는 `c.dim() == 2` 로 갈라 배치 축을 넣고, 끝에서 `squeeze(0)` 한다.

**추론 모양을 반드시 지원해야 한다.** 학습만 되는 모델은 파이프라인에 꽂히지 않는다 —
이것을 놓쳐서 실패한 적이 있어 회귀 테스트로 고정했다
(`tests/test_predict_dataset.py::TestRankNetShapes`).

## 8. 기동 분류 헤드 — 왜 붙였고 무엇을 얻었는가

`predict_maneuver=True`(기본)면 `man_head` 가 5종을 분류한다.

```
MANEUVER_CLASSES = ("직진", "좌회전", "우회전", "유턴", "후보 밖 경로")
```

마지막 클래스가 핵심이다. 후보 방식은 "어느 후보도 따라가지 않는다"를 표현할 자리가
없는데 실제 궤적의 22% 가 그렇다.

**`trunk` 의 출력 `t` 를 좌표 헤드와 공유한다.** 같은 궤적을 설명하는 두 출력이 서로
모순되지 않으려면 같은 표현에서 나와야 한다.

> `trunk` 를 **한 번만** 부른다. 처음 구현에서는 `self.head(z)` 와 `self.trunk(z)` 를
> 따로 불러 `trunk` 가 forward 당 2회 실행됐다. `trunk` 안에 dropout 이 있으므로 학습
> 모드에서 두 호출의 결과가 달라지고(실측: 같은 입력에 대한 최대 차이 0.25), "공유한다"는
> 설계 의도가 **정작 학습 중에** 성립하지 않았다. 계산도 두 배였다.
> 같은 수정으로 `state_dict` 중복 키 6개도 없어졌다 (`self.head` 가 `trunk`·`wp_head` 를
> 다시 등록하고 있었다).

### 얻은 것과 얻지 못한 것

| 기동 라벨 | 전체 | 후보 안 표본만 |
|---|---:|---:|
| **모델의 기동 헤드** | **83.5%** | 91.9% |
| 사전확률 1순위 후보에서 읽기 | 77.0% | **98.6%** |
| 예측 궤적 최근접 후보 | 77.8% | 94.8% |

- **전체로는 모델이 낫다**(83.5% 대 77.0%) — "후보 밖"을 표현할 수 있어서다.
- **후보 안 표본만 보면 지도에서 읽는 쪽이 압도적이다**(98.6% 대 91.9%). 그 구간에서는
  지도가 기동을 거의 결정하므로 추론으로 이길 여지가 별로 없다.
- 그래서 결론은 **"기동은 지도에서, 좌표는 모델에서"** 다. 기동 헤드를 붙인 이유는
  규칙을 이기는 것이 아니라 ① 전체 정확도 ② **학습되는 출력이어야 정확도를 잴 수 있다**
  는 것이다. 사후 주석은 검증 대상이 없다.

"후보 밖" 판정만 따로 보면 모델만 할 수 있는 일이다.

| | 정밀도 | 재현율 | 기저 |
|---|---:|---:|---:|
| 모델 기동 헤드 | **67.4%** | **53.6%** | 22.0% |
| 좌표를 후보에 맞춰 판정 | 48.6% | 16.7% | 21.2% |
| 규칙 기반 | 불가능 | — | — |

기동 헤드를 붙여도 ADE 는 변하지 않았다 (3.05m 그대로).

### 진입 도로 이름은 모델이 내지 않는다

도로 이름은 지도마다 다른 어휘라 고정 클래스로 분류할 수 없다. `_from_waypoints` 가
**모델이 고른 기동과 같은 기동을 가진 후보** 중 예측 궤적에 가장 가까운 것에서 가져온다.
"후보 밖"이면 붙이지 않는다 — 따라가지 않는 도로를 적으면 그냥 오정보다.

## 9. 손실 — ADE 가 손실이 아니다

```python
전체 = coord_loss(좌표) + man_weight · CrossEntropy(기동)      # man_weight 기본 1.0
```

**평가 지표는 ADE 지만 손실은 ADE 가 아니다.** 기본은 축별 Huber 다.

```python
per   = huber_loss(pred, tgt, delta=2.0, reduction="none").sum(-1)   # x,y 각각 → 더함
loss  = (per * tmask).sum() / tmask.sum()
```

Huber 는 `|e| ≤ delta` 면 `0.5e²`, 그 밖이면 `delta(|e| − 0.5delta)` 다. `delta = 2.0m`
는 차로 폭(3.5m)의 절반 즈음이다 — **같은 차로 안의 오차는 2차로, 차로를 벗어난 오차는
1차로** 다룬다는 뜻이다.

### 9.1 ADE 와 정확히 무엇이 다른가

| | ADE (평가) | 손실 (학습) |
|---|---|---|
| 거리 | 유클리드 `‖e‖₂` | x·y 축별 Huber 의 **합** |
| 큰 오차 | 선형 | 선형 (delta 밖) |
| 작은 오차 | 선형 | **2차** |
| 회전 불변 | 예 | **2m 이하만** |
| 평균 단위 | 표본별 평균 → 표본 간 평균 | (표본, 시각) 쌍 전체를 한 번에 평균 |

**회전 불변이 아니다.** 축별 Huber 를 더하면 1차 구간에서 방향에 따라 벌점이 달라진다.

| 오차 크기 | 축 방향 | 대각선 | 비율 |
|---:|---:|---:|---:|
| 1 m | 0.500 | 0.500 | 1.00× |
| 2 m | 2.000 | 2.000 | 1.00× |
| 4 m | 6.000 | 7.314 | 1.22× |
| 16 m | 30.000 | 41.255 | **1.38×** |

2차 구간에서는 `e_x² + e_y² = ‖e‖²` 이라 자동으로 회전 불변이지만, 1차 구간에서는
대각선 오차가 최대 √2 배 세게 벌점을 받는다.

**평균 단위도 다르다.** 손실은 배치의 모든 (표본, 시각) 쌍을 한 번에 평균하므로 관측
시각이 많은 표본이 더 큰 비중을 갖는다. ADE 는 표본별로 평균한 뒤 표본 간 평균이라 모든
표본이 같은 비중이다. 미래 관측이 6초인 표본은 2초인 표본보다 손실에 3배 기여하는데,
긴 관측 표본이 곧 어려운 표본(6초에서 후보 밖 35.5%)이라 나쁜 방향은 아니다. 다만
**학습 목표와 보고 지표가 같지 않다는 것은 알고 있어야 한다.**

### 9.2 그러면 ADE 를 그대로 쓰면 어떻게 되는가 — 실측

`--wp-loss {huber, huber_norm, ade, l2}` 로 바꿔 가며 100 epoch 씩 돌렸다.
시드 0~2 의 **시험 ADE**:

| `--wp-loss` | 무엇인가 | 시험 ADE (시드 0/1/2) |
|---|---|---|
| `huber` (기본) | 축별 Huber, delta=2m | 3.05 / 3.03 / 3.04 m |
| `huber_norm` | `‖e‖` 에 Huber (회전 불변) | 3.05 m |
| **`ade`** | **평가 지표 그 자체** | **3.03 / 3.03 / 3.03 m** |
| `l2` | 평균 제곱오차 | 3.11 / 3.13 / 3.11 m |

읽는 법.

- **`huber` 와 `ade` 는 구별되지 않는다** (차이 0.01m, 시드폭 0.02m 안). ADE 를 직접
  최소화해도 손해가 없다.
- **의미 있는 것은 L2 를 쓰지 않는 것이다** (+0.08m, 시드폭 밖). 차선 변경·급정지 같은
  큰 오차가 제곱으로 커져 기울기를 지배하고, 평범한 직진까지 나빠진다.
- 기본을 `huber` 로 둔 이유는 성능 우위가 아니라 **오차 0 에서 미분이 정의된다**는 것뿐
  이다 (`‖e‖` 는 0 에서 미분 불가라 `clamp(min=1e-12)` 로 막아야 한다).

> 처음 이 코드를 쓸 때 "ADE 를 손실로 쓰면 기울기 크기가 오차와 무관해 0 근처 미세
> 수렴이 나쁘다" 고 주석에 적었다. **측정이 뒷받침하지 않아 지웠다.** 이 규모에서는
> 관찰되지 않는 이론적 우려였다.

### 9.3 마스킹과 제외 규칙

**시각 마스크가 필요하다.** `target_offsets` 는 관측이 끊기면 짧아진다 (5초 지평에 2점만
있을 수 있다). 없는 시각을 0 으로 두고 손실에 넣으면 "원점으로 돌아온다"를 학습한다.

**기동 정답이 임의인 표본은 -100 으로 둔다.** 동률 후보의 기동이 갈리는 경우
(`maneuver_ambiguous`)는 정답 자체가 후보 목록 순서로 정해진 것이므로 학습·채점에서
빼야 한다 (`ignore_index=-100`). 넣으면 모델이 순서를 외운다.

**`matched=false` 표본은 빼지 않는다.** 실제 궤적이라는 정답이 있고, 기동 정답은
"후보 밖" 이다. 그래서 학습 표본이 114,169개 — rank 과제(17,097개)의 6.7배다.

### 9.4 두 손실 항의 크기 균형

좌표 항은 미터 눈금(수렴 시 ~6), 기동 항은 nats 눈금(~0.4)이다. `man_weight` 기본값
1.0 에서는 **좌표 항이 압도적으로 크다.** 기동 헤드를 붙여도 ADE 가 변하지 않은 것
(3.05m 그대로)이 그 결과다 — 기동 학습이 좌표 학습을 방해하지 않는다. 반대로 기동
정확도를 더 밀어붙이려면 `--man-weight` 를 올려야 하고, 그때 ADE 가 나빠지는지 확인해야
한다 (아직 재지 않았다).

## 10. 재현

```bash
python examples/train_predict_model.py --data out/predict_dataset \
    --task waypoints --epochs 100 --out out/predict_model
```

RTX PRO 6000 에서 100 epoch **26초**. 하이퍼파라미터는
`hidden=128 · dropout=0.1 · lr=1e-3 · weight_decay=1e-4 · batch=512 · seed=0`,
AdamW + 코사인 스케줄. 검증 최고 epoch 87 의 가중치를 `waypointnet_best.pt` 로 저장한다.

분할은 **시나리오 단위**다 — 학습 114,169 / 검증 13,941 / 시험 23,453. 0.5초 간격 인접
표본은 서로 거의 같아서 표본 단위 무작위 분할은 성능을 크게 과대평가한다.

쓰는 쪽:

```python
from traffic_llm.predict_model import TorchPredictor
cfg.predictor = TorchPredictor("out/predict_model/waypointnet_best.pt",
                               mode="waypoints")
```

`examples/run_deepaccident.py` 는 **이 모델을 기본으로 쓴다** — `--predictor` 를 주지
않으면 `out/predict_model/waypointnet_best.pt` 를 찾고, 없거나 torch 가 없으면 규칙
기반으로 내려가며 이유를 출력한다. 규칙 기반을 강제하려면 `--no-predictor` 다.
모드는 모델 클래스에서 판정하므로 `--predictor-mode` 를 줄 필요가 없다.
라이브러리 기본값(`PipelineConfig.predictor`)은 torch 선택 의존성을 지키기 위해
여전히 `None`(규칙 기반)이다.

## 11. 이 모델이 하지 않는 것

- **다중 모드를 내지 않는다.** 궤적 하나를 확률 1.0 으로 낸다. 규칙 기반과 `RankNet` 은
  "직진 60% / 좌회전 40%" 처럼 분포를 내는데, LLM 브리핑은 그 분포로 위험을 따진다.
  **이것이 가장 큰 손실이다.** 다음 단계는 기동별 좌표를 함께 내는 다중 모드 회귀이고,
  그러려면 `PredictedPath` 여러 개를 내는 계약으로 확장해야 한다.
- **노면을 보장하지 않는다.** 지도 제약이 없다. Town05 한 시나리오에서 예측 웨이포인트
  2,035개 중 도로 미매칭이 0개였지만(규칙 기반은 3,403개 중 16개), 다른 타운에서 같은지는
  확인하지 않았다.
- **후보 폴리라인의 형상을 보지 않는다.** 입력은 후보를 12차원으로 요약한 것이고 회전각·
  길이는 있지만 곡선 모양은 없다. `candidate_waypoints` 를 입력에 넣으면 더 오를 여지가
  있다 (데이터에는 이미 저장돼 있다).
- **신호·정지선·차선 표시가 없다.** 데이터에 없으므로 모델도 배울 수 없다.
- **상호작용을 보지 않는다.** 한 액터를 독립적으로 예측한다. 앞차가 멈춰 있어서 감속하는
  것 같은 관계는 입력에 들어 있지 않다.
