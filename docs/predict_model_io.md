# 경로 예측 모델의 입력·출력 명세

`prediction.predict()` 의 예측기를 **학습 모델로 교체**할 때의 계약이다. 입력이 무엇이고
출력이 어떤 형태여야 하는지, 지도학습 데이터의 각 필드가 무엇인지 적는다.

규칙 기반 알고리즘 자체는
[`predicted_path_algorithm.md`](predicted_path_algorithm.md) 에 있다.

---

## 1. 왜 이렇게 나눴는가

예측기는 `PredictContext → List[PredictedPath]` 함수다. 기본값은
`prediction.rule_predict`(지도 제약 규칙)이고, 여기에 학습 모델을 끼울 수 있다.

```python
from traffic_llm.config import PipelineConfig
from traffic_llm.predict_model import TorchPredictor

cfg = PipelineConfig()
cfg.predictor = TorchPredictor("model.pt")        # 지정하지 않으면 규칙 기반
```

두 가지를 규약으로 못박았다.

- **입력은 `PredictContext` 하나로 모은다.** 규칙 기반이 쓰는 것과 정확히 같은
  정보이며, 학습 데이터도 이 구조에서 만든다. 그래야 학습과 추론의 입력이 어긋나지
  않는다 — 학습 때 본 적 없는 특징으로 추론하거나 그 반대가 되면 조용히 성능이
  떨어진다.
- **좌표 생성은 공유한다.** rank 모드는 `prediction.candidate_to_path()` 를 그대로
  쓴다. 시간축 재샘플링·시작점 보정·잘림 표시가 규칙 기반과 같아야 두 예측기의
  출력을 비교할 수 있다.

---

## 2. 입력 — `PredictContext`

```python
@dataclass
class PredictContext:
    actor: ActorState                 # 위치·속도·방위·클래스·도로 매칭 + 과거 궤적
    horizon_s: float                  # 예측 지평 [s] (기본 5)
    candidates: List[Candidate]       # 지도가 낸 후보 경로
    t_s: Optional[float]              # 스냅샷 시각 (학습 데이터 식별용)
    scenario_id: str
```

`ActorState.track_history` 가 **관측된 과거 궤적**이다 — `(시각[s], e, n)` 목록이고
오래된 것 → 최근 순, 마지막 원소가 현재 시각·현재 위치다. `KinematicsTracker` 가
`finalize()` 에서 붙인다(속도·방위를 추정하려고 이미 유지하던 버퍼다). 평활하지 않은
원 관측값이다 — 평활을 미리 하면 급감속·차선변경 신호가 지워지고, 그것은 모델이 할 일이다.

이력을 넣은 이유: `world_xy` 만 주면 모델이 볼 수 있는 것은 "지금 어디에 있는가" 뿐이다.
정지 후 재가속, 감속 추세, 차선변경 진행 같은 **시간 패턴**은 한 시점의 좌표로 표현되지
않는다. 이력이 있으면 LSTM·GRU·트랜스포머 같은 계열 구조를 쓸 수 있다 (§6.2).

```python
@dataclass
class Candidate:
    maneuver: str                     # 직진 / 좌회전 / 우회전 / 유턴
    prior: float                      # 규칙 기반 사전확률
    polyline: List[Tuple[float,float]]  # ENU, 5m 간격
    to_road: Optional[str]            # 진입 도로 이름
```

`candidates` 는 `roadmap.downstream_paths()` 의 **원본**이다. 규칙 기반이 마지막에
하는 동일 기하 병합(`merge_identical`)은 **적용되지 않은** 상태다 — 모델은 병합 전
후보를 각각 평가하고, 병합은 출력 단계에서 일어난다.

`candidates` 가 비면(도로 미매칭, 정지, 속도 미확정) 모델을 호출하지 않고
`fallback`(기본: 규칙 기반)으로 넘어간다.

### 2.1 특징 인코딩

`predict_model.encode(ctx)` 가 두 배열을 만든다.

**`global` — 길이 22** (액터·도로 상태)

| # | 값 | 비고 |
|---|---|---|
| 0 | 속도 [m/s] | |
| 1 | 속도 있음 (0/1) | 결측을 0 으로 채우므로 플래그가 필요하다 |
| 2 | 가속도 [m/s²] | |
| 3 | 가속도 있음 | |
| 4,5 | 방위 sin, cos | 각도를 스칼라로 주면 0°/360° 경계에서 큰 오차를 학습한다 |
| 6 | 방위 있음 | |
| 7 | 예측 지평 [s] | |
| 8 | 추적 나이 [s] | 짧으면 속도·기동 판정이 보류된 상태다 |
| 9 | 존재 확신도 | |
| 10 | 위치 정확도 | 존재 확신도와 **다른 값**이다 |
| 11–17 | 클래스 원-핫 | car, van, truck, bus, motorcycle, bicycle, person |
| 18 | 횡오프셋 [m] | 진행 방향 기준 좌(+)/우(−) |
| 19 | 차선 위치 비율 | `lane_index / lane_count` |
| 20 | 다음 교차로 거리 [m] | 없으면 200 |
| 21 | 진행방향 확신 (0/1) | 0 이면 방위·차선이 반대일 수 있다 |

**`history` — 5 × 5** (과거 5초, 1초 간격)

행 순서는 **오래된 것 → 최근**(t-5 … t-1)이라 계열 모델에 그대로 넣을 수 있다.
현재 시각은 원점이므로 넣지 않는다.

| # | 값 | 비고 |
|---|---|---|
| 0,1 | de, dn | **현재 위치 기준 상대좌표** [m] — 절대 ENU 를 넣으면 지역 좌표계의 원점을 외운다 |
| 2,3 | vde, vdn | 그 시각의 1초 속도 벡터 [m/s] |
| 4 | valid | 그 시각에 관측이 있었는가 (0/1) |

관측 주기(2Hz/10Hz)와 무관하게 **모양이 고정**이다 — 데이터셋마다 입력 모양이 바뀌면
계약이 성립하지 않는다. 격자가 `target_offsets` 와 같은 1초 간격이라 과거 5초 → 미래
5초가 대칭이다.

> **`valid` 가 없으면 안 된다.** 트랙이 방금 생겼으면 이력이 전부 0 인데, 플래그가
> 없으면 모델이 "그 5초 동안 정지해 있었다"로 읽는다. 실측으로 전체 레코드의 **평균
> 유효 단계는 3.12/5** 이고 5단계를 모두 채운 것은 34.1% 뿐이다 — 결측이 예외가 아니다.
>
> 가장 오래된 단계(t-5)의 속도는 t-6 과의 차분이라, 추적기는 **6초**를 보관한다.
> 5초만 받으면 그 행의 속도가 0 이 되어 "그때 멈춰 있었다"로 오해된다 (실측으로 그랬다).

**`candidates` — 후보 수 × 12**

| # | 값 | 비고 |
|---|---|---|
| 0 | 규칙 기반 사전확률 | 모델이 이것을 보정하는 형태로 학습할 수 있다 |
| 1,2 | 회전각 sin, cos | 후보 첫 구간 방위 − 액터 방위 |
| 3 | 회전각 / 180 | 스칼라 형태도 함께 (부호가 좌우를 뜻한다) |
| 4 | 후보 경로 길이 [m] | |
| 5 | 길이 / 지평거리 | 1 미만이면 도로망 끝에서 잘린다 |
| 6 | 폴리라인 정점 수 | |
| 7 | 진입 도로 이름 있음 | |
| 8–11 | 기동 원-핫 | 직진, 좌회전, 우회전, 유턴 (`MANEUVERS` 순서) |

> **결측은 0 + 플래그로 표현한다.** 0 이 "값이 0" 인지 "모른다" 인지 구별되지
> 않으면 모델이 결측을 특정 값으로 오해한다. 이 파이프라인은 속도·방위·가속도를
> 판정 불가일 때 `None` 으로 두는 것이 설계 원칙이므로 결측이 드물지 않다.

## 3. 출력 — 두 가지 모드

### 3.1 `mode="rank"` (기본, 권장)

모델이 후보마다 점수를 내고 softmax 로 확률을 만든다. **기하는 지도에서 나온 것을
그대로 쓴다.**

```
forward(global[22], candidates[N,12]) → scores[N]
```

이 모드를 권장하는 이유가 셋이다.

- **노면을 벗어나지 않는다.** 좌표를 회귀하면 학습이 덜 된 상태에서 건물 안이나
  역주행 경로를 낸다.
- **학습 데이터가 적어도 동작한다.** 학습하는 것은 확률뿐이고, 최악의 경우 사전확률
  근처로 수렴한다.
- **문제가 실제로 여기 있다.** 규칙 기반의 기동 라벨 정확도는 이미 94.6% 인데
  **후보 선택은 61.1%** 다 (아래 §5). 같은 기동으로 갈 수 있는 진출로가 여럿일 때
  어느 쪽인지가 남은 문제다.

### 3.2 `mode="waypoints"`

모델이 지평까지의 좌표를 직접 낸다. **후보 중 하나를 고르지 않으므로 후보 집합의
상한에 걸리지 않는다** — 실측으로 ADE 가 규칙 기반보다 24% 낮고 후보 오라클도 넘는다
(§5.7). 대가는 **다중 모드를 잃는 것**이다 (궤적 하나, 확률 1.0).

```
forward(global[22], candidates[N,12]) → offsets[K,2]
```

출력은 **현재 위치 기준 상대 좌표**이고 t = 1..K초에 해당한다 (t=0 은 항상 원점이므로
내지 않는다). 절대 ENU 좌표를 회귀하면 지역 좌표계의 원점 위치를 외우게 되어 다른
타운에서 전혀 동작하지 않는다.

기동은 좌표와 함께 **모델이 분류한다** — `(좌표, 기동 로짓)` 을 내면
`_from_waypoints` 가 로짓의 argmax 를 라벨로 쓴다. 클래스는 `MANEUVER_CLASSES`
(직진·좌회전·우회전·유턴 + **후보 밖 경로**) 5종이다. 좌표만 내면 후보에 맞춰 되짚지만
정확도가 낮으므로 권장하지 않는다 (§5.8). 구현은
`traffic_llm/predict_nets.py` 의 `WaypointNet` 이다.

### 3.3 어떤 경우에도 출력 형태는 같다

```python
PredictedPath(
    maneuver: str,        # 직진 / 좌회전 / 우회전 / 유턴 / 정지 유지 / …
    probability: float,   # 한 액터의 경로들에 대해 합이 1
    waypoints: List[Tuple[float,float]],   # 1초 간격 ENU
    horizon_s: float,
    to_roads: List[str],
    truncated: bool,      # 도로망 끝에서 잘렸는가 (정지 아님)
)
```

하류(직렬화·BEV·상호작용 분석)가 이 형태를 그대로 쓴다.

**확률 합은 1 이어야 한다.** `rank` 모드는 softmax 결과를 **자르지 않고 전부** 낸다.
상위 k개만 남기면 합이 1 미만이 되고(후보가 많을 때 실측 0.45 까지 떨어졌다),
자연어·JSON·BEV 가 모두 "합 1" 을 전제하므로 표시가 어긋난다. 상위 3개만 보이는 것은
**자연어 렌더링 단계**의 일이고, 예측기는 관여하지 않는다. 규칙 기반도 같다.
회귀 테스트: `tests/test_pipeline.py::TestPluggablePredictor::test_rank_probabilities_sum_to_one`.

### 3.4 모델 저장 형식

`TorchPredictor` 는 `torch.save(model, path)` 로 저장한 **모델 객체**를 기대한다.
`state_dict` 만 있으면 구조를 알 수 없으므로 **예외를 던진다** — 조용히 잘못된 예측을
내는 것보다 낫다. TorchScript(`torch.jit.save`)는 `ScriptedRankPredictor` 를 쓴다.

## 4. 지도학습 데이터

```bash
python examples/make_predict_dataset.py \
    --root /home/sryu/inclab-nas/DeepAccident \
    --carla-maps ./carla_map \
    --out out/predict_dataset
```

`--split` / `--type` / `--town` / `--limit` 로 범위를 좁힐 수 있다.

전체(607 시나리오)를 한 프로세스로 돌리면 몇 시간 걸린다. `--shard I/N` 으로 나눠
동시에 돌리고 합치는 것이 실용적이다 (16조각 ≈ 15분).

```bash
for i in $(seq 0 15); do
    python examples/make_predict_dataset.py --root <루트> --carla-maps ./carla_map \
        --out out/predict_dataset --shard $i/16 &
done; wait
python examples/make_predict_dataset.py --merge --out out/predict_dataset
```

조각 분배는 라운드로빈이고 시나리오 목록이 정렬돼 있으므로 **실행마다 같다** —
일부 조각만 다시 돌려 다시 합칠 수 있다. `--merge` 는 조각 파일을 지우지 않는다.

### 4.1 정답을 어떻게 정하는가

추론 시점에는 미래를 모르지만 **데이터셋에는 시나리오 끝까지 다 있다.** 그래서 시각
t 의 액터가 실제로 어디로 갔는지를 t 이후 스냅샷에서 읽어 정답으로 쓴다.

```
1) t 이후 1초 간격으로 실제 위치를 읽는다 (지평까지)
2) 각 후보 폴리라인까지의 점–선분 거리를 재고 평균한다
   (시작점은 두 경로가 같으므로 제외 — 포함하면 모든 후보가 같이 낮아진다)
3) 평균 거리가 가장 작은 후보가 정답
4) 그 거리가 3.0m 를 넘으면 후보 집합 밖의 행동으로 본다
```

3.0m 는 차로 폭(3.5m)의 절반보다 조금 작다. 그보다 벗어났으면 다른 차로나 다른
경로를 간 것이다.

> **일치하지 않는 표본을 버리지 않는다.** `matched=false` 로 표시해 남긴다. 차선
> 변경·노면 이탈·급정지처럼 후보 집합이 표현하지 못하는 행동이 실제로 존재하고,
> 조용히 버리면 데이터가 실제보다 쉬워 보인다. 학습에서 걸러내는 것은 쓰는 쪽의
> 선택으로 남긴다.

이 정답은 **추정값이다.** 실제 궤적은 사실이지만 "그 시점에 어느 후보를 의도했는가"는
관측할 수 없다. 시나리오 전체를 보고 정하므로 추론 시점의 정보만으로 정하는 것보다
정답에 가깝다는 것이 이 방식의 근거다.

#### 정답이 후보에 **없는** 경우가 21.4% 다 — 가장 중요한 한계

후보는 `roadmap.downstream_paths` 가 지도에서 만든 것이다. **실제 궤적이 그중 하나라는
보장이 전혀 없다.** 차선 변경, 노면 이탈, 급감속, 도로 매칭 실패가 모두 후보 밖으로
나간다. 전체 151,563 레코드에서 실측한 값이다.

| | 레코드 | 비율 |
|---|---:|---:|
| 정답이 후보에 있다 (`matched=true`) | 119,082 | 78.6% |
| **정답이 후보에 없다** (`matched=false`) | **32,481** | **21.4%** |

예측 구간이 길수록 급격히 늘어난다 — 멀리 볼수록 지도를 따라간다는 가정이 깨진다.

| 미래 관측 길이 | 2초 | 3초 | 4초 | 5초 | 6초 |
|---|---:|---:|---:|---:|---:|
| 정답이 후보에 없는 비율 | 4.5% | 6.0% | 11.6% | 22.1% | **35.5%** |

가장 가까운 후보까지의 거리로 보면 원인이 갈린다. 35.5% 가 3–5m 로 **차로 하나 옆**이고
(차선 변경), 42.9% 가 5–10m, 21.4% 가 10–30m 다.

이 한계는 **규칙 기반도 똑같이 진다.** `rule_predict` 도 후보들에만 확률을 나누므로
"지도 밖으로 간다"를 말할 수 없다. 학습 모델의 결함이 아니라 **후보 생성의 한계**이며,
그래서 §5 의 비교는 여전히 같은 조건에서 성립한다. 다만 §5 수치를 **"정답이 후보에 있는
경우로 한정한 값"** 으로 읽어야 한다 (§5.6).

#### 정답이 하나로 정해지지 않는 표본 — 반드시 알아야 할 것

차량이 아직 갈림길에 닿지 않았으면 **여러 후보가 실제 궤적과 똑같이 가깝다.** 교차로
전 100m 를 직진하는 동안에는 그 교차로에서 좌회전할 후보와 직진할 후보가 같은 구간을
공유하므로 평균 거리가 소수점까지 같다. 그때 3) 의 `argmin` 은 정답을 고르는 것이
아니라 **후보 목록의 순서를 고르는 것**이다.

그래서 각 레코드에 `tied_best`(동률 후보 전부)와 `label_ambiguous` 를 넣는다. 판정
기준은 평균 거리 차이 `TIE_EPS_M = 0.05m` 다 (좌표를 mm 로 반올림해 저장하므로 그보다
작은 차이는 의미가 없다).

이것을 표시하지 않으면 두 가지가 조용히 망가진다.

- **학습**이 목록 순서를 외운다 — 정답이 임의인 표본에서 순서와 상관된 특징을 찾는다.
- **평가**가 부풀려진다. 사전확률의 `argmax` 도 같은 목록 순서로 동률을 깨므로
  `argmin` 과 **구조적으로 일치한다.** 임의 표본을 세면 정확도가 높게 나오지만
  그 값은 성능이 아니다 (§5 의 실측 대비 참고).

동률 후보들이 모두 같은 기동이면 후보 인덱스만 임의고 기동 라벨은 유효하다. 기동까지
갈리는 경우는 `maneuver_ambiguous=true` 로 따로 표시한다 (좌회전·우회전 후보가 아직
갈라지지 않은 구간 등).

### 4.2 레코드 형식 (JSONL, 한 줄 = 한 표본)

| 필드 | 뜻 |
|---|---|
| `scenario_id` · `dataset_split` · `town` · `t_s` | 식별 |
| `actor_id` · `actor_class` | 액터 |
| **`global`** | 길이 22 특징 (§2.1) |
| **`candidates`** | 후보 수 × 12 특징 |
| **`history`** | 5 × 5 과거 궤적 (§2.1). `valid` 칸으로 결측을 구별한다 — 평균 유효 단계 3.12/5 |
| `candidate_meta[]` | 후보별 `maneuver`, `prior`, `to_road`, `n_vertices` — 사람이 읽고 오류를 찾기 위한 것. 학습 입력은 `candidates` 다 |
| **`best_candidate`** | 정답 후보 인덱스 (분류 정답) |
| `maneuver` | 그 후보의 기동 라벨 |
| **`target_offsets`** | 실제 미래 궤적, 현재 위치 기준 상대 좌표 1초 간격 (회귀 정답). index 0 은 항상 `[0,0]` |
| **`candidate_waypoints[]`** | 규칙 기반이 실제로 내보내는 후보별 웨이포인트, 같은 상대좌표·같은 시각 격자. `target_offsets` 와 index 끼리 바로 비교해 ADE/FDE 를 낼 수 있다 — 이것이 없으면 좌표 회귀 모델과 규칙 기반을 비교할 수 없다 |
| `origin_enu` | 절대 좌표로 되돌릴 기준점 |
| `match_error_m` | 정답 후보와 실제 궤적의 평균 거리 = **정답의 신뢰도** |
| `candidate_errors_m[]` | 후보별 거리. 소프트 라벨이나 순위 학습에 쓸 수 있다 |
| `matched` | `match_error_m ≤ 3.0` |
| `future_complete` | 지평 끝까지 관측됐는가. false 면 `target_offsets` 가 짧다 |
| **`tied_best[]`** | 정답과 구별할 수 없는 후보 인덱스 전부. 길이 1 이면 정답이 유일하다 |
| **`label_ambiguous`** | `len(tied_best) > 1` — `best_candidate` 가 목록 순서로 정해졌다는 표시 |
| `maneuver_ambiguous` | 동률 후보들의 기동이 서로 다른가. false 면 기동 라벨은 유효하다 |
| `margin_m` | 정답 후보와 **동률이 아닌** 다음 후보의 거리 차이. 클수록 정답이 분명하다. 후보가 전부 동률이면 `null` |

`manifest.json` 에 표본 수·설정·기동 분포·집계와 `label_quality`(모호 표본 수와
`tie_eps_m`)가 들어간다.

### 4.3 쓰는 쪽에서 정해야 할 것

- **`label_ambiguous=true` 표본을 어떻게 다룰지.** 이것이 가장 중요하다. 셋 중 하나다.
  - **제외** — 단일 라벨 교차엔트로피를 쓸 때 가장 안전하다.
  - **집합 라벨** — `tied_best` 에 확률을 균등 분배한 소프트 타깃으로 학습한다
    (`target = onehot(tied_best).mean()`). 표본을 버리지 않으면서 임의성을 넣지 않는다.
  - **`margin_m` 으로 가중** — 정답이 분명한 표본에 큰 가중을 준다.

  평가에서는 **반드시 제외하거나 "동률 집합 안에 들면 정답"으로 채점해야 한다.**
  `best_candidate` 하나만 정답으로 세면 목록 순서에 맞춘 모델이 유리해진다.
- **`matched=false` 표본을 어떻게 다룰지.** 제외하거나, 별도 클래스("후보 밖")를
  두거나, `match_error_m` 으로 가중할 수 있다.
- **`future_complete=false` 표본.** `target_offsets` 가 지평보다 짧다. 회귀에는
  마스킹이 필요하고, 분류에는 그대로 쓸 수 있다.
- **후보 수가 표본마다 다르다.** rank 모델은 가변 길이를 받아야 한다 (패딩 + 마스크,
  또는 후보별 독립 스코어링).
- **분할.** `dataset_split` 이 데이터셋의 train/val 을 그대로 담고 있으므로 그것을
  쓰면 된다. 같은 시나리오의 표본이 train/val 에 섞이지 않게 하려면
  `scenario_id` 로 나눈다 — 인접 시각 표본은 서로 매우 비슷해서 무작위 분할은
  성능을 과대평가한다.

## 5. 베이스라인 — 학습으로 얻을 것이 어디에 있는가

DeepAccident **전체 607 시나리오**로 생성한 데이터셋(표본 151,563개, 실패 0)에서
규칙 기반 사전확률의 성능을 쟀다. `examples/predict_dataset_baseline.py` 로 재현된다.

### 5.1 데이터 구성

| 구분 | 표본 | 비고 |
|---|---:|---|
| 전체 | 151,563 | mini 8,906 · train 119,204 · val 23,453 · 타운 7종 |
| `matched=false` | 32,481 (21.4%) | 실제 궤적이 어느 후보와도 3m 안에서 맞지 않음 |
| 후보 1개뿐 | 64,300 | 고를 것이 없다 (분류에는 쓸 수 없음) |
| **다후보 표본** | **54,782** | 후보 선택을 채점할 수 있는 표본 |
| ├ 정답 라벨 임의 | 32,473 (59.3%) | 그중 기동까지 임의 5,582 |
| └ **정답 라벨 유일** | **22,309 (40.7%)** | 아래 수치의 모집단 |

### 5.2 사전확률의 실제 성능

| 지표 | 값 |
|---|---|
| **사전확률 argmax = 정답 후보** | **61.1%** (13,636/22,309) |
| 사전확률 argmax 의 기동 = 정답 기동 | **94.6%** |
| 무작위 선택 기대값 | 25.2% |
| 정답 후보의 평균 궤적 오차 | 0.42 m |

> **라벨이 임의인 표본을 넣으면 69.8% 로 보인다** (임의 표본만 놓고 보면 75.7%).
> 그 값은 성능이 아니다 — `argmin(오차)` 과 `argmax(사전확률)` 이 **같은 목록 순서로
> 동률을 깨기 때문에** 구조적으로 일치한다. 처음 2개 시나리오로 재서 이 문서에 적었던
> 71.4% 도 같은 이유로 부풀려진 값이었다. 반대쪽 관대한 상한은 "동률 집합 안에 들면
> 정답"으로 채점한 **77.5%** 다. 실제 값은 61.1% 와 77.5% 사이에 있고, 단일 라벨로
> 학습·평가하려면 61.1% 를 기준으로 삼는 것이 맞다.

### 5.3 어디에 배울 것이 있는가

**기동 판별은 이미 94.6% 다.** 남은 것은 같은 기동으로 갈 수 있는 진출로가 여럿일 때
어느 쪽인지다. 다후보 표본의 후보 구성이 그것을 보여준다.

| 후보의 기동 집합 | 다후보 표본 | 그중 라벨 유일 |
|---|---:|---:|
| 직진만 (진출로 여럿) | 34,165 (62.4%) | 10,854 |
| 유턴 + 직진 | 9,699 (17.7%) | 7,161 |
| 우회전 + 좌회전 | 6,792 (12.4%) | 3,435 |
| 우회전만 (진출로 여럿) | 2,303 (4.2%) | 301 |
| 그 외 | 1,823 (3.3%) | 558 |

62% 가 **"직진 후보 여럿"** 이고, 사전확률 규칙은 그것들에 정규화된 **같은 값**을 주므로
구별하지 못한다. 학습 모델이 기여할 곳은 좌/우 판별이 아니라 **진출로 선택**이고,
그 정보는 지도 기하(진출로 곡률·차선 수)와 액터 상태(차선 위치·횡오프셋·속도)에 있다 —
사전확률 규칙은 둘 다 쓰지 않는다.

### 5.4 어려움이 어디서 오는가 (참고)

| 후보 수 | top-1 | 표본 | 무작위 |
|---:|---:|---:|---:|
| 2 | 59.2% | 3,230 | 50.0% |
| 3 | 71.4% | 4,096 | 33.3% |
| 4 | 70.2% | 3,109 | 25.0% |
| 5 | 46.3% | 7,660 | 20.0% |
| 6 | 83.4% | 2,898 | 16.7% |
| 8 | 32.1% | 722 | 12.5% |

후보 5개·8개에서 무너지는 것은 CARLA 의 차로 분할 도로가 많은 교차로다 — 같은 방향으로
가는 여러 도로 id 중 하나를 골라야 한다.

미래 관측 길이가 길수록 정확도가 **떨어진다**(2초 72.4% → 6초 53.5%). 짧은 미래는
차량이 아직 직진 중이어서 어느 후보를 골라도 비슷하게 맞기 때문이다. 즉 긴 관측 표본이
진짜 어려운 표본이다.

### 5.5 학습 결과 (RankNet, 100 epoch)

`examples/train_predict_model.py` 기본 설정으로 100 epoch 학습한 결과다. RTX PRO 6000
에서 **2초**, 재현 명령은 그대로다.

```bash
python examples/train_predict_model.py --data out/predict_dataset \
    --epochs 100 --out out/predict_model
```

분할은 시나리오 단위다 — 학습 17,097(시나리오 432) / 검증 2,001(50) / 시험 3,211(104).
시험셋은 데이터셋의 `val` 분할이고, 검증셋은 학습셋에서 떼어냈다. 보고는 검증 최고
epoch(75)의 가중치로 낸다.

| top-1 | 학습 | 검증 | **시험** |
|---|---:|---:|---:|
| **RankNet** | 79.35% | 74.61% | **68.79%** |
| 규칙 기반 (`prediction.py`) | 61.44% | 58.67% | 60.95% |
| 무작위 기대치 | 26.64% | 26.69% | 26.68% |
| **향상** | +17.90%p | +15.94%p | **+7.85%p** |

기동 라벨도 94.83% → 95.52% 로 올랐다 (이미 높아 여지가 작다).

> **시드 변동이 약 1%p 다.** 시드 0~3 의 시험 top-1 은 68.79 / 69.70 / 68.70 / 69.48%
> (평균 69.2%)다. 소수 둘째 자리까지 인용하면 없는 정밀도를 주장하는 것이므로, 결론은
> **"규칙 기반 61.0% 대 학습 모델 69% 내외, +8%p"** 로 읽어야 한다.

**타운별 시험 성능** — 모든 타운에서 규칙을 이긴다. 전체 수치가 한 타운에 끌려간 것이
아니다.

| 타운 | 표본 | RankNet | 규칙 | 향상 |
|---|---:|---:|---:|---:|
| Town03 | 791 | 65.1% | 53.2% | +11.9%p |
| Town07 | 699 | 60.8% | 55.5% | +5.3%p |
| Town04 | 641 | 74.3% | 75.4% | **-1.1%p** |
| Town10HD | 484 | 77.9% | 65.5% | +12.4%p |
| Town05 | 434 | 67.5% | 53.7% | +13.8%p |
| Town01 | 162 | 75.9% | 71.0% | +4.9%p |

정직하게 읽어야 할 것 넷.

- **위 수치는 "정답이 후보에 있는 경우"로 한정한 값이다.** 학습·평가에서
  `matched=false` 를 제외했다. 후보 밖으로 간 21.4% 를 포함한 값은 §5.6 에 있다.
  **이것이 가장 중요한 조건이다.**
- **학습 79.4% vs 시험 68.8% — 과적합이 있다.** dropout 0.1 · weight decay 1e-4 만
  걸었다. 학습 표본이 17,097 개뿐이라는 것이 근본 원인이다 (§5.7 의 좌표 회귀는 같은
  데이터에서 114,169 개를 쓴다).
- **Town04 는 규칙 기반이 더 낫다**(-1.1%p). 모든 타운에서 이기는 것이 아니다.
- **검증 74.6% vs 시험 68.8%.** 검증셋은 학습셋과 같은 시나리오 풀(`train`+`mini`)에서
  나왔고 시험셋은 데이터셋의 `val` 분할이다. 타운 구성이 다르다 — 학습은 Town05 가 33%,
  시험은 Town03·Town07 이 47% 이고 그 두 타운이 양쪽 방법 모두에서 어렵다. 즉 시험셋이
  더 어려운 쪽이고, 검증 수치를 성능으로 보고하면 안 된다.
- **여전히 후보의 지도 기하는 특징에 없다.** 진출로의 곡률·차선 수·폭을 넣지 않았다
  (§5.3 이 지목한 정보). 그것을 넣으면 더 오를 여지가 있다.

### 5.6 후보 밖으로 간 경우를 포함하면 — 그리고 모델은 그것을 모른다

§5.5 는 `matched=false` 를 뺀 값이다. 후보가 있는 **시험 레코드 전부**(23,453)에 대해,
정답이 후보에 없는 경우를 **오답으로 세면** 다음과 같다.

| | 시험 정확도 |
|---|---:|
| RankNet | 73.0% |
| 규칙 기반 | 71.4% |
| 정답이 후보에 있는 비율 = **달성 가능한 상한** | 78.8% |

> 이 표의 모집단은 §5.5 와 다르다 — 후보가 1개뿐인 레코드(고를 것이 없어 자동으로
> 맞는다)를 포함하므로 절대값을 §5.5 의 70.6% 와 직접 비교하면 안 된다. 여기서 읽어야
> 할 것은 **상한이 78.8% 로 막혀 있다**는 사실이다. 후보 생성을 개선하지 않으면 모델을
> 아무리 키워도 그 위로 갈 수 없다.

**모델은 "정답이 여기 없다"를 신호로 내지 못한다.** 다후보 시험 레코드에서 최대 softmax
확률의 판별력을 재면 **AUC 0.281** 이다. 0.5 가 판별 불가인데 그보다 **낮다** — 즉
확신도가 **역전**돼 있다. 정답이 없을 때 오히려 더 확신한다 (중앙값 0.950 대 0.502).
차선 변경 직전에는 지도가 직진 하나를 강하게 밀기 때문이다.

| 다후보 시험 레코드의 최대확률 | p10 | p25 | p50 | p75 |
|---|---:|---:|---:|---:|
| 정답 있음 (n=8,160) | 0.261 | 0.341 | 0.502 | 0.855 |
| 정답 없음 (n=1,540) | 0.347 | 0.596 | **0.950** | 0.999 |

**따라서 확신도 임계값으로 걸러내려는 시도는 하면 안 된다.** 반대 방향으로 작동한다.

#### 그런데 "후보 밖"은 예측 가능하다 (실측 AUC 0.873)

같은 `global` 특징에 후보 요약(개수·사전확률 최대/최소/엔트로피·지평 대비 길이비)만
붙여 이진 분류기를 학습했다. 시나리오 단위 분할, 60 epoch.

| 시험 AUC | 임계 0.5 정밀도 | 임계 0.7 정밀도 | 기저 비율 |
|---:|---:|---:|---:|
| **0.873** | 69.0% (재현율 49.3%) | 80.8% (재현율 25.0%) | 21.2% |

즉 **abstain(후보 밖) 클래스를 두는 것이 옳고, 지금 있는 특징만으로도 학습된다.**
권장 설계는 후보 점수에 "후보 밖" 로짓 하나를 더해 N+1 로 softmax 하고,
`matched=false` 표본의 정답을 그 인덱스로 두는 것이다. 그러면

- 후보 밖으로 갈 확률이 페이로드에 **수치로** 나가고 (지금은 조용히 후보 중 하나를 고른다),
- 학습에서 `matched=false` 21.4% 를 버리지 않게 되고,
- §5.5 의 조건부 수치와 §5.6 의 무조건 수치가 하나로 합쳐진다.

**rank 모드에는 아직 넣지 않았다.** 다만 §5.7 의 좌표 회귀는 후보를 고르지 않으므로
상한 자체가 없고, 거기에 붙인 기동 분류 헤드가 **"후보 밖" 을 실제로 판정한다** —
정밀도 67.4% · 재현율 53.6% (§5.8). 즉 이 구멍은 waypoints 쪽에서 이미 메워지기
시작했다.

### 5.7 좌표를 직접 내면 상한이 사라진다 (WaypointNet, 실측)

§5.6 의 78.8% 상한은 "후보 중 하나를 고른다"는 형태에서 온다. 좌표를 직접 회귀하면
그 형태를 벗어난다. 척도도 바뀐다 — 후보 인덱스 정확도가 아니라 **ADE/FDE** 다.

```bash
python examples/train_predict_model.py --data out/predict_dataset \
    --task waypoints --epochs 100 --out out/predict_model
```

학습 표본이 **114,169 개**다 (rank 의 17,097 개의 6.7배). `matched=false` 를 뺄 이유가
없고 — 실제 궤적이라는 정답이 있다 — 후보 인덱스의 모호성도 회귀와 무관하기 때문이다.
100 epoch 24초.

| 시험셋 (23,453) | ADE | FDE |
|---|---:|---:|
| **WaypointNet** | **3.05 m** | **5.30 m** |
| 규칙 기반 (top-1 후보) | 4.01 m | 7.00 m |
| 등속 직진 | 4.13 m | 7.42 m |
| **후보 최선 = 후보 방식의 오라클** | 3.75 m | — |

**ADE −24%, FDE −24%.** 그리고 **후보 오라클(3.75m)까지 넘었다**(3.05m) — 후보를 완벽히
골라도 도달할 수 없는 정확도다. §5.6 이 말한 상한이 실제로 사라진 것이다.

이득이 어디서 오는지 나눠 보면 분명하다.

| 시험셋 분해 | 표본 | WaypointNet | 규칙 기반 | 차이 |
|---|---:|---:|---:|---:|
| 정답이 후보에 있음 | 18,478 | 2.57 m | 2.86 m | −0.29 m (−10%) |
| **정답이 후보에 없음** | 4,975 | **4.84 m** | 8.26 m | **−3.42 m (−41%)** |

쉬운 쪽에서는 10% 만 낫다. 큰 이득은 **후보 방식이 구조적으로 맞힐 수 없는 21%** 에서
나온다. 이것이 좌표 회귀를 쓰는 이유다.

#### 설계에서 중요한 두 가지

**등속을 기준선으로 깔고 보정만 학습한다** (`WaypointNet(residual=True)`, 기본값).
마지막 층을 0 으로 초기화하므로 **학습 전 출력이 정확히 등속**이다. 5초 예측의 상당
부분이 직진 유지이므로 안전한 곳에서 출발하는 셈이고, 실패해도 등속으로 떨어진다.

**입력을 모델 안에서 표준화한다** (`fit_normalizer`, 학습셋만 사용). 특징 눈금이
속도 0~30, 교차로 거리 0~200, 원-핫 0/1 로 크게 다르다. 정규화 없이는 30 epoch 동안
손실이 10.28→10.03 으로 거의 움직이지 않고 등속을 넘지 못했다. 평균·표준편차는 버퍼로
저장되어 `torch.save(model)` 에 함께 실리므로 추론 전처리를 따로 맞출 필요가 없다.

#### 대가 — 무엇을 잃는가

- **다중 모드를 잃는다.** 규칙 기반과 rank 는 "직진 60% / 좌회전 40%" 처럼 **분포**를
  낸다. 좌표 회귀는 궤적 하나를 확률 1.0 으로 낸다. LLM 브리핑은 이 분포로 위험을
  따지므로 이것이 가장 큰 손실이다.
- **기동 라벨을 따로 마련해야 한다.** 좌표 회귀는 좌표만 낸다 — 기동은 공짜로 나오지
  않는다. 어디서 가져올지에 따라 정확도가 크게 다르므로 §5.8 에서 따로 다룬다.
- **노면 보장이 없다.** 다만 실측에서는 나쁘지 않았다 — Town05 시나리오의 예측
  웨이포인트 2,035개 중 도로 미매칭 **0개**(규칙 기반은 3,403개 중 16개). 등속 기준선과
  후보 요약 입력이 궤적을 도로 위에 붙여 두는 것으로 보인다. 다른 타운에서 같은지는
  확인하지 않았다.

### 5.8 기동 라벨은 어디서 오는가 — 그리고 그 정확도

`PredictedPath.maneuver` 는 rank 모드에서는 **모델이 고른 후보의 라벨**이므로 모델
출력이다. 그러나 waypoints 모드에서 좌표만 회귀하면 **기동은 모델 출력이 아니다** —
어딘가에서 만들어 붙여야 하고, 그러면 그 정확도를 따로 재야 한다.

정답은 `matched=true` 인 레코드의 `maneuver`(실제 궤적이 따라간 후보의 기동)이고,
`matched=false` 면 "후보 밖" 이 정답이다. 기동이 모호한 표본(`maneuver_ambiguous`)은
정답 자체가 임의이므로 제외한다. 시험셋 22,632개(후보 안 17,657 / 후보 밖 4,975).

| 라벨을 만드는 방식 | 전체 | 후보 안 표본만 |
|---|---:|---:|
| A 사전확률 1순위 후보의 기동 | 77.0% | **98.6%** |
| B 예측 궤적에 가장 가까운 후보 | 77.8% | 94.8% |
| **C 모델의 기동 분류 헤드** (현재) | **83.5%** | 91.9% |
| D  A + C 의 후보밖 판정 결합 | 83.7% | 91.9% |

> A·B·D 는 학습 전 비교 시점의 값이고 C 는 현재 저장된 모델의 값이다. C 의 재학습 전후 차이는 83.9→83.5% 로 시드 수준의 변동이며 순위는 바뀌지 않는다.

읽는 법이 중요하다.

- **전체로는 C 가 가장 낫다**(83.5%). A·B 는 "후보 밖" 을 거의 표현하지 못하는데 그것이
  표본의 22% 다. A 는 원리적으로 불가능하다 — 후보에만 확률을 나누므로.
- **후보 안 표본만 보면 A 가 압도적이다**(98.6%). 그 구간에서는 지도가 기동을 거의
  결정하고, A 는 그것을 지도에서 그냥 읽는다. 모델이 추론으로 이길 여지가 별로 없다.
- 그래서 결론은 **"기동은 지도에서, 좌표는 모델에서"** 다. 후보를 따라가는 차량의 기동
  라벨만 필요하다면 rank/규칙 경로가 낫고, waypoints 모드는 좌표를 얻으려고 쓰는 것이다.

`WaypointNet(predict_maneuver=True)`(기본값)이 C 를 구현한다. `MANEUVER_CLASSES` 는
`직진 · 좌회전 · 우회전 · 유턴 · 후보 밖 경로` 5종이고, 좌표 헤드와 **같은 은닉 표현**
(`trunk`)에서 나온다 — 같은 궤적을 설명하는 두 출력이 서로 모순되지 않게 하려는 것이다.
기동 헤드를 붙여도 ADE 는 그대로였다 (3.05m).

계약: 모델은 좌표 하나를 내거나 `(좌표, 기동 로짓)` 을 낸다. 후자면 `_from_waypoints`
가 로짓의 argmax 를 라벨로 쓴다. 로짓 개수가 5개가 아니면 **예외를 던진다** — 조용히
엉뚱한 라벨을 붙이는 것보다 낫다. 진입 도로 이름은 지도마다 다른 어휘라 모델이 분류할
수 없으므로, **모델이 고른 기동과 같은 기동을 가진 후보** 중 예측 궤적에 가장 가까운
것에서 가져온다. "후보 밖" 이면 도로 이름을 붙이지 않는다.

#### 모델만 할 수 있는 것 — "후보 밖" 판정

§5.6 은 이 판정을 규칙 기반이 **아예 할 수 없다**고 적었다. 모델의 기동 헤드는 한다.

| | 정밀도 | 재현율 | 기저 |
|---|---:|---:|---:|
| 모델 기동 헤드 | **67.4%** | **53.6%** | 22.0% |
| 좌표를 후보에 맞춰 판정(B 방식) | 48.6% | 16.7% | 21.2% |
| 규칙 기반 | — (불가능) | — | — |

즉 §5.6 이 지적한 구멍은 **좌표 회귀 + 기동 헤드 쪽에서 이미 메워지기 시작했다.**
rank 모드에 abstain 클래스를 넣는 일은 여전히 남아 있다.

> **앞선 서술을 정정한다.** 이 문서와 커밋에서 "사전확률 1순위 후보의 라벨을 베끼는 것은
> 결함이고, 다후보 표본의 8.9% 가 좌표와 모순된다" 고 적었다. 8.9% 는 사실이지만 그것은
> **라벨과 좌표의 내부 일관성**이고 **정확도가 아니다.** 정답 대비로 재면 그 방식(A)이
> 후보 안 표본에서 98.6% 로 가장 정확하고, 일관성을 맞추려 바꾼 방식(B)은 94.8% 로
> **떨어졌다.** 두 지표를 같은 것으로 다룬 것이 잘못이었다. 현재는 C 를 쓰는데, 그 근거는
> 일관성이 아니라 **전체 정확도(83.9%)와 후보 밖 판정 능력**이다.

#### 그래서 어느 쪽을 쓰나

**둘은 배타적이지 않다.** 좌표 정확도가 필요하면 waypoints(ADE 3.05m), 기동 분포와
후보 안 기동 라벨이 필요하면 rank/규칙(98.6%)이다. 자연스러운 다음 단계는 **rank 로
기동 분포를 내고 각 기동의 좌표를 회귀하는 것**(다중 모드 회귀)이지만, 그러려면
`PredictedPath` 여러 개를 내는 계약으로 확장해야 하고 아직 하지 않았다.

## 6. 학습

### 6.1 준비된 스크립트

```bash
python examples/train_predict_model.py --data out/predict_dataset \
    --epochs 100 --out out/predict_model
```

GPU 가 있으면 자동으로 쓴다(`--device auto`). 하는 일은 다음과 같다.

- `matched=false` · `label_ambiguous=true` 표본 제외 (§4.3)
- **과거 궤적 인코더** `--history-encoder {transformer,gru,mlp,none}` (기본 transformer).
  구조와 실측 비교는 [`waypointnet.md`](waypointnet.md) §2.5 — 이득은 ADE 0.04m(1.2%)로
  작지만 시드 3회에서 일관되고, 이력 보유량을 따라간다
- **시나리오 단위** 분할 — 기본은 데이터셋의 `val` 을 시험셋으로, 학습셋에서 다시 10%를
  검증셋으로 떼어낸다. `--split-by scenario` 는 시나리오 id 의 crc32 로 나눈다.
- 가변 후보 수를 패딩 + 마스크로 묶어 GPU 배치 학습
- 같은 표본에 대한 **규칙 기반(`prediction.py`) 성능을 함께 출력** — 비교 대상
- `ranknet_best.pt`(검증 최고 epoch) · `ranknet_final.pt`(마지막 epoch) ·
  `train_report.json`(하이퍼파라미터·분할·epoch별 이력) 저장

> **시험셋으로 epoch 을 고르지 않는다.** 그러면 보고하는 시험 성능이 낙관적으로
> 편향된다. 그래서 학습셋에서 검증셋을 따로 뗀다. `--val-frac 0` 으로 끄면 마지막
> epoch 만 저장한다.

> **표본 단위 무작위 분할을 쓰지 않는다.** 스냅샷 주기가 0.5초라 인접 표본은 서로 거의
> 같다. 같은 시나리오가 학습·시험에 모두 들어가면 시험 성능이 사실상 학습 성능이 된다.
> 회귀 테스트: `tests/test_predict_dataset.py::TestTrainSplit`.

### 6.2 모델

`traffic_llm/predict_nets.py` 의 `RankNet` 이다. **패키지 모듈에 두는 것이 중요하다** —
학습 스크립트 안에 정의하면 `torch.save` 가 `__main__.RankNet` 으로 저장해 다른
프로세스에서 `AttributeError: Can't get attribute 'RankNet'` 이 난다.

```python
class RankNet(nn.Module):
    def forward(self, g, c):
        if c.dim() == 2:                    # 추론: g[22], c[N,12] → [N]
            g = g.reshape(1, -1).expand(c.shape[0], -1)
        else:                               # 학습: g[B,22], c[B,N,12] → [B,N]
            g = g.unsqueeze(1).expand(-1, c.shape[1], -1)
        return self.mlp(torch.cat([g, c], dim=-1)).squeeze(-1)
```

**두 모양을 모두 받아야 한다.** 학습만 되는 모델은 `TorchPredictor` 에 꽂히지 않는다.
저장은 `torch.save(model, path)` — `state_dict` 만 저장하면 `TorchPredictor` 가 거부한다
(§3.4).

### 6.3 손실 (직접 학습할 때)

`best_candidate` 를 정답으로 한 교차엔트로피다. **후보 수가 표본마다 다르니** 표본별로
한 번씩 부르고 손실을 모아 step 하거나(아래), 패딩 + 마스크로 배치한다
(`predict_nets.masked_scores`).

```python
for r in samples:
    if not r["matched"] or r["label_ambiguous"] or len(r["candidates"]) < 2:
        continue                       # §4.3 — 임의 라벨을 단일 정답으로 쓰지 않는다
    g = torch.tensor(r["global"])                    # [22]
    c = torch.tensor(r["candidates"])                # [N,12]
    target = torch.tensor(r["best_candidate"])
    loss = torch.nn.functional.cross_entropy(
        model(g, c).unsqueeze(0), target.unsqueeze(0)
    )
    loss.backward()                    # 32개마다 opt.step(); opt.zero_grad()
```

`label_ambiguous` 표본을 버리지 않고 쓰려면 `tied_best` 를 균등 분포 소프트 타깃으로
넣는다 (`cross_entropy` 는 확률 타깃을 받는다).

```python
t = torch.zeros(len(r["candidates"]))
t[r["tied_best"]] = 1.0 / len(r["tied_best"])
loss = torch.nn.functional.cross_entropy(model(g, c).unsqueeze(0), t.unsqueeze(0))
```

쓰는 쪽:

```python
cfg.predictor = TorchPredictor("out/predict_model/ranknet_best.pt", mode="rank")
```

학습 없이 규칙 기반 베이스라인만 보려면 `examples/predict_dataset_baseline.py` 를 쓴다.

## 7. 이 계약이 보장하지 않는 것

- **모델 품질을 검증하지 않는다.** 예측기가 이상한 확률을 내도 파이프라인은 그대로
  쓴다. `rank` 모드에서 점수 개수가 후보 수와 다르면 예외를 던지는 것이 유일한 검사다.
- **`waypoints` 모드는 노면을 보장하지 않는다.** 지도 제약이 없으므로 건물 안이나
  역주행 경로가 나올 수 있다. BEV 는 도로 미매칭 경로를 그리지 않지만 payload 에는
  들어간다.
- **정답은 추정값이다** (§4.1). "실제로 간 경로"는 사실이지만 "의도한 후보"는 아니다.
- **후보 집합에 정답이 있다는 보장이 없다** (§4.1 · §5.6). 실측 21.4%. `rank` 모드는
  **반드시 후보 중 하나를 고른다** — "후보 밖"을 표현할 수 없고, 확신도로도 감지되지
  않는다(AUC 0.281, 역전). 이것이 현재 계약의 가장 큰 구멍이다.
- **신호·차선 표시가 여전히 없다.** 데이터에 없으므로 모델도 배울 수 없다.
